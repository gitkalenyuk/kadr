Updates commands

6 commands in the Updates category. Each one works the same from the editor UI, REST, MCP and kadrctl.

  • update.checkCheck for updates
  • update.downloadDownload update
  • update.installInstall update
  • update.settingsUpdate settings
  • update.skipSkip this version
  • update.statusUpdate status

update.check

Check for updates

No undo stepMenu › Check for updates…MCP update_check

Asks GitHub whether a newer Kadr is published — Settings → Updates → "Check now" and Menu → "Check for updates…". Downloads latest.json (+ latest.json.sig) from the release repository (stable: the latest regular release; beta: the newest release including pre-releases, via the GitHub API), verifies its Ed25519 signature with the key built into Kadr and compares versions with semver rules (1.1.0-beta.1 < 1.1.0-rc.1 < 1.1.0). Nothing is downloaded or installed. The release channel is PRIVATE (Kadr is distributed by invitation): without an access token, or with a token that cannot read the repository, the check succeeds with private=true, access="none", available=false and a reason ("ask the vendor for the latest installer"), the updater state becomes no_access and no event is published; save a GitHub token with update.settings {github_token} (or set KADR_UPDATE_TOKEN) to receive updates automatically. available=true means a newer version exists; skipped=true means the user chose "Skip this version" for it (it is still reported here but never announced automatically); can_install=false (with reason) means this build cannot self-update — portable builds, development builds without a signing key, or a release without a Windows installer — so open release_url instead. A pre-release is never offered on the stable channel. Publishes update.available when a newer, not skipped version is found. Fails with not_available when GitHub cannot be reached, not_found when the repository has no release yet, and internal when the signature does not verify (the update is refused).

Parameters

ParameterTypeDescription
channelstringRelease channel to look at: "stable" = regular releases only (the GitHub "latest" release), "beta" = also pre-releases such as 0.2.0-beta.1. Omit to use the channel saved in settings (update.settings).
One of stable beta

Returns

{current, latest, available, channel, prerelease, notes_markdown, notes_url, release_url, published_at, size (installer bytes), installer, signed, skipped, required (current is older than min_supported), min_supported, portable, can_install, reason, checked_at, private (no access to the private channel), access public|token|none}.

Examples

Check the configured channel

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.check \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run update.check
// MCP tool: update_check
{}

Look for pre-releases too

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.check \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"channel":"beta"}'
kadrctl run update.check --channel beta
// MCP tool: update_check
{
  "channel": "beta"
}

update.download

Download update

No undo stepSettings › Updates › Download & installMCP update_download

Downloads the installer of the newest version found by update.check (runs a check first when none was done in this session) into %TEMP%\Kadr-update\ and verifies its exact size and SHA-256 against the signed latest.json; a file that does not match is deleted and the update is refused. Runs in the background and returns immediately (state "downloading") unless wait=true; progress arrives as update.progress events, completion as update.ready, errors as update.failed. An installer already downloaded and verified is reused. Does not install anything — call update.install afterwards. Refused with not_available for portable builds, development builds without a signing key and releases without a Windows installer (open release_url instead), and with conflict when Kadr is already up to date.

Parameters

ParameterTypeDescription
waitbooleanBlock until the download finished and was verified (can take minutes for ~100 MB) instead of returning at once.
Default false

Returns

The update.status object (state downloading, ready or failed).

Examples

Start downloading in the background

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.download \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run update.download
// MCP tool: update_download
{}

Download and wait until verified

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.download \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"wait":true}'
kadrctl run update.download --wait
// MCP tool: update_download
{
  "wait": true
}

update.install

Install update

No undo stepSettings › Updates › Download & installMCP update_install

Installs the newest version and restarts Kadr — the "Download & install" button. Downloads and verifies the installer first if update.download has not finished (SHA-256 + size from the Ed25519-signed latest.json, checked again right before running), then starts it detached with /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS /RELAUNCH and closes the desktop app about a second later. The installer upgrades in place, keeps all projects and settings, closes running Kadr processes (Kadr.exe, kadr-server.exe, kadr-mcp.exe) and starts Kadr again when done, so API clients lose their connection for a minute. UNSAVED WORK: projects are saved after every command, but running exports are cancelled. Requires confirm=true as a safety check. In the headless server nothing quits by itself: the result asks to exit. Refused for portable builds and builds without a signing key (not_available).

Parameters

ParameterTypeDescription
confirmrequiredbooleanMust be true: confirms that Kadr may close (running exports stop) and the installer may run.

Returns

{started, version, installer, args (the exact installer arguments), quitting (the app exits shortly), message}.

Examples

Install the downloaded update and restart

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.install \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"confirm":true}'
kadrctl run update.install --confirm
// MCP tool: update_install
{
  "confirm": true
}

update.settings

Update settings

No undo stepSettings › UpdatesMCP update_settings

Reads or changes the updater preferences stored in <data dir>/settings.json (key "update"). Without arguments it only returns them. auto_check (default on) makes Kadr check GitHub in the background after startup, at most once every 24 hours, never blocking the editor (a private channel without access stays silent); channel picks stable releases or also beta pre-releases. Regular builds such as 1.0.0 use the stable channel; builds that are themselves pre-releases default to beta. github_token stores the GitHub access token the vendor gave you for the private release channel (a fine-grained token with read-only Contents access to the release repository, or a classic token with repo scope); it is saved as update.github_token in settings.json, used only for requests to the GitHub API, and NEVER returned — results only show github_token_set and github_token_source (env = the KADR_UPDATE_TOKEN environment variable, which wins over the saved one; settings). Pass "" to remove it. Changing settings does not check by itself — call update.check afterwards.

Parameters

ParameterTypeDescription
auto_checkbooleanCheck for updates automatically on startup (once a day). Omit to leave unchanged.
channelstring"stable" (regular releases) or "beta" (also pre-releases). Omit to leave unchanged.
One of stable beta
github_tokenstringGitHub access token for the private release channel (github_pat_… or ghp_…); "" removes the saved token. Never echoed back. Omit to leave unchanged.

Returns

{auto_check, channel, last_check (RFC 3339, omitted before the first check), skipped_version, github_token_set, github_token_source (env|settings, omitted when none)}.

Examples

Read the settings

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.settings \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run update.settings
// MCP tool: update_settings
{}

Join the beta channel

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.settings \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"channel":"beta"}'
kadrctl run update.settings --channel beta
// MCP tool: update_settings
{
  "channel": "beta"
}

Turn automatic checks off

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.settings \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"auto_check":false}'
kadrctl run update.settings --auto_check false
// MCP tool: update_settings
{
  "auto_check": false
}

Save the access token from the vendor

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.settings \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"github_token":"github_pat_EXAMPLE"}'
kadrctl run update.settings --github_token github_pat_EXAMPLE
// MCP tool: update_settings
{
  "github_token": "github_pat_EXAMPLE"
}

Remove the saved access token

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.settings \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"github_token":""}'
kadrctl run update.settings --github_token ''
// MCP tool: update_settings
{
  "github_token": ""
}

update.skip

Skip this version

No undo stepSettings › Updates › Skip this versionMCP update_skip

Remembers a version as skipped — "Skip this version" under the release notes. A skipped version is no longer announced by the automatic startup check (no update.available event, no badge) but update.check still reports it with skipped=true, and any newer version is offered again normally. Only one version can be skipped; clear=true forgets it. Stored in settings.json.

Parameters

ParameterTypeDescription
clearbooleanForget the skipped version instead (version is ignored).
Default false
versionstringVersion to skip, e.g. "0.2.0" (a leading v is accepted). Omit to skip the latest version found by update.check.

Returns

The saved settings {auto_check, channel, last_check, skipped_version, github_token_set, github_token_source}.

Examples

Skip 0.2.0

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.skip \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"version":"0.2.0"}'
kadrctl run update.skip --version 0.2.0
// MCP tool: update_skip
{
  "version": "0.2.0"
}

Stop skipping

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.skip \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"clear":true}'
kadrctl run update.skip --clear
// MCP tool: update_skip
{
  "clear": true
}

update.status

Update status

No undo stepSettings › UpdatesMCP update_status

Returns the updater state without contacting GitHub: state (idle | checking | up_to_date | available | downloading | ready | installing | failed | no_access — the private release channel cannot be read, see latest.reason), the result of the last check (latest, null before the first check), download progress, the verified installer path when ready, the last error, the saved settings, whether this is a portable build and whether this build carries an update signing key. Poll it every 1-2 s during update.download, or listen to the update.progress / update.ready / update.failed events instead.

Parameters

No parameters.

Returns

{state, current, latest (update.check result or null), downloaded_bytes, total_bytes, progress 0..1, installer_path, error, settings{auto_check, channel, last_check, skipped_version, github_token_set, github_token_source}, portable, signing_key, repo, releases_url (private repository), changelog_url (public release notes), website}.

Examples

Poll the updater

curl -X POST http://127.0.0.1:7777/api/v1/commands/update.status \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run update.status
// MCP tool: update_status
{}
