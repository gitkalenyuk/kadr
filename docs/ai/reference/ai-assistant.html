assistant.always_allow.revoke

Stop always allowing in AI chat

No undo stepUser onlyMCP assistant_always_allow_revoke

Takes back "Always for this chat" (assistant.approve decision always): the named command, or every command when command is omitted, no longer runs without asking in this chat — the chat's permission mode decides again (ask_every asks before every change, ask_risky before risky ones). The current list is always_allow of assistant.session. Works while the chat is running (the next call is checked against the new list). A status event with state always_allow (message and the remaining commands) is stored in the transcript and published as assistant.status. Fails with not_found when the named command is not always allowed; clearing an empty list does nothing.

Parameters

ParameterTypeDescription
session_idrequiredstringChat session id ("ses_…") from assistant.sessions, assistant.new or assistant.send.
commandstringCommand to ask about again (e.g. "project.delete"); omit to clear the whole list.
project_idstringProject the chat belongs to ("prj_…"). Omit for chats without a project; for an existing session it only narrows the search.

Returns

{removed: [commands that ask again], always_allow: [commands still always allowed]}.

Examples

Ask again before deleting projects

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.always_allow.revoke \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"command":"project.delete","project_id":"prj_1a2b3c4d5e6f","session_id":"ses_0a1b2c3d4e5f"}'
kadrctl run assistant.always_allow.revoke --command project.delete --project_id prj_1a2b3c4d5e6f --session_id ses_0a1b2c3d4e5f
// MCP tool: assistant_always_allow_revoke
{
  "command": "project.delete",
  "project_id": "prj_1a2b3c4d5e6f",
  "session_id": "ses_0a1b2c3d4e5f"
}

Clear the whole list

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.always_allow.revoke \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"project_id":"prj_1a2b3c4d5e6f","session_id":"ses_0a1b2c3d4e5f"}'
kadrctl run assistant.always_allow.revoke --project_id prj_1a2b3c4d5e6f --session_id ses_0a1b2c3d4e5f
// MCP tool: assistant_always_allow_revoke
{
  "project_id": "prj_1a2b3c4d5e6f",
  "session_id": "ses_0a1b2c3d4e5f"
}

assistant.approve

Answer AI approval

No undo stepUser onlyMCP assistant_approve

Answers an approval card of a running chat (assistant.approval_request event): allow runs the action, deny tells the assistant the user refused (it will not retry), always allows it and every later call of the same command in this chat without asking (not offered for paid generation, which is confirmed every time; assistant.always_allow.revoke takes it back). The permission_resolved event says always=true then. For paid generation the approved call gets the estimate's confirm token automatically. Unanswered cards are denied after 10 minutes.

Parameters

ParameterTypeDescription
decisionrequiredstringallow, deny, or always (allow this command for the rest of the chat).
One of allow deny always
request_idrequiredstringId of the approval card (permission.id of the event, "perm_…").
session_idrequiredstringChat session id ("ses_…") from assistant.sessions, assistant.new or assistant.send.
messagestringOptional note for the assistant when denying (e.g. "use the local voice instead").

Returns

{ok: true}.

Examples

Allow

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.approve \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"decision":"allow","request_id":"perm_1a2b3c4d","session_id":"ses_0a1b2c3d4e5f"}'
kadrctl run assistant.approve --decision allow --request_id perm_1a2b3c4d --session_id ses_0a1b2c3d4e5f
// MCP tool: assistant_approve
{
  "decision": "allow",
  "request_id": "perm_1a2b3c4d",
  "session_id": "ses_0a1b2c3d4e5f"
}

assistant.cli.custom

Custom AI agent CLI

No undo stepChanges the systemUser onlyMCP assistant_cli_custom

Adds, replaces or removes a user-defined CLI agent. spec describes how to run it: command, args (templates with {prompt}, {mcp_config}, {mcp_config_json}, {mcp_url}, {kadr_mcp}, {session}, {model}, {workdir}, {instructions}), resume_args, model_args, prompt_via (arg|stdin), output (stream-json for Claude-compatible JSON, jsonl, plain), transport (stdio|gateway), tools (meta = five meta-tools, the default | full = one tool per command), env (KEY=value), key_env (names filled from the vault), session_pattern. Custom agents are not limited to Kadr's tools, so chats using them need allow_outside. Saved in the assistant settings.

{id, removed?} or the agent's status entry.

{started: true, job_id, agent, job: "install"} (background) or {job_id, ok, status} with wait=true.

assistant.cli.login

Sign in AI agent CLI

No undo stepCredentialsUser onlyMCP assistant_cli_login

Signs a CLI agent in ("Sign in" in the settings). Without api_key it runs the CLI's own sign-in: the provider's page opens in the browser (or a terminal window for CLIs that only sign in interactively) and Kadr polls until the agent reports it is signed in, the login ends or 5 minutes pass — in the background with a job_id, output lines (URLs, device codes) as assistant.cli.output and the end as assistant.cli.done {job_id, agent, ok, status}. With api_key the key is stored in the OS-encrypted vault for the agent's auth variable (env, default the agent's first auth key) and the new status is returned at once.

Parameters

ParameterTypeDescription
agentrequiredstringCLI agent id: claude, codex, gemini, antigravity, cursor, copilot, opencode, qwen, amp, goose, crush, kimi, aider, cline, droid, warp, or a custom id ("cli:" prefix allowed).
api_keystringSign in with this API key / token instead of the browser login (stored in the vault).
envstringEnvironment variable for api_key (one of the agent's key_specs; default its first auth key).
terminalbooleanOpen a visible terminal window even when the CLI has a non-interactive login.
waitbooleanBlock until the sign-in finishes and return the status.

Returns

{started: true, job_id, agent, job: "login"} (background), {job_id, ok, status} with wait=true, or {ok, status} with api_key.

Examples

Sign in to Codex in the browser

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.cli.login \
  -H "Authorization: Bearer $KADR_TOKEN" \

assistant.keys.add

Add AI provider keys

No undo stepCredentialsSettings › AI assistantUser onlyMCP assistant_keys_add

Stores API keys of an assistant API provider in the encrypted vault (Windows DPAPI / macOS Keychain) — Settings → AI assistant → provider → Keys. Many keys per provider are supported; they are used in order and the next one takes over on invalid / quota / payment / rate-limit errors. Pass one api_key (with an optional label), a batch in keys (one per line, "label: key" or NAME=value lines; blank lines, # comments and duplicates are skipped and reported by line without the secret) or a file (.txt/.env, .csv/.tsv, .json). New keys are tested with the provider's free list-models request unless test=false. Keys are never returned, only masked previews. Local servers (Ollama, LM Studio) need no key.

Parameters

ParameterTypeDescription
providerrequiredstringAPI provider id ("openrouter", "anthropic"…; "api:" prefix allowed).
api_keystringOne API key.
filestringAbsolute path of a .txt/.env/.csv/.json file with keys.
keysstringSeveral keys, one per line ("label: key" allowed).
labelstringOptional label for api_key (e.g. "Work account").
testbooleanTest the new keys with the free list-models request.
Default true

Returns

{provider, added: [{id, label, preview, status}], duplicates, rejected: [{line, reason, preview}], tested?: [{id, preview, status, ok, error}], keys: total}.

Examples

Paste a key

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.keys.add \
  -H "Authorization: Bearer $KADR_TOKEN" \

}

Paste several keys

assistant.keys.list

No undo stepUser onlyMCP assistant_keys_list

Lists the API keys stored for the assistant's API providers (key pools in the OS-encrypted vault) in the order they are tried, with masked previews only (sk-…a1b2): label, status (unknown / ok / exhausted / invalid / rate_limited), whether it is usable now, last error (redacted), cooldown, remaining quota when reported, uses and failures. assistant.stop

Stop AI assistant

No undo stepUser onlyMCP assistant_stop

Stops the running turn of a chat (the Stop button): the model stream or the CLI agent process tree is ended, pending approval cards are closed as stopped and the run finishes with a done event (stopped=true). Edits already made stay (undo them with edit.undo or assistant.revert). Returns stopped=false when the chat was not running.

Parameters

ParameterTypeDescription
session_idrequiredstringChat session id ("ses_…") from assistant.sessions, assistant.new or assistant.send.

Returns

{stopped: bool}.

Examples

Stop

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.stop \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"session_id":"ses_0a1b2c3d4e5f"}'
kadrctl run assistant.stop --session_id ses_0a1b2c3d4e5f
// MCP tool: assistant_stop
{
  "session_id": "ses_0a1b2c3d4e5f"

assistant.test

Test AI assistant provider

No undo stepUser onlyMCP assistant_test

Checks that an assistant backend works. API providers: the key pool is tested with the provider's free list-models call (local servers: that they answer) and, with prompt=true, one tiny real request ("Reply with OK", a few tokens — billed by the provider). CLI agents: detection and sign-in status, and with prompt=true one tiny headless run through Kadr's runner (uses the agent's plan or key). Returns ok, the state, how long it took and the reply.

Parameters

ParameterTypeDescription
providerrequiredstringBackend id from assistant.providers: "api:<provider>" (e.g. api:anthropic, api:openrouter, api:ollama) or "cli:<agent>" (e.g. cli:claude, cli:codex).
modelstringModel id of the provider (assistant.models); "default" or omitted = the provider's default model.
promptbooleanAlso send one tiny real prompt (costs a few tokens).

Returns

{ok, provider, model?, state, detail, latency_ms, models?, reply?, usage?, error?, hint?}.

Examples

Is my Anthropic key fine?

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.test \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"provider":"api:anthropic"}'
kadrctl run assistant.test --provider api:anthropic
// MCP tool: assistant_test
{
  "provider": "api:anthropic"
}

Tiny real prompt with Claude Code

curl -X POST http://127.0.0.1:7777/api/v1/commands/assistant.test \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"prompt":true,"provider":"cli:claude"}'
kadrctl run assistant.test --prompt --provider cli:claude
// MCP tool: assistant_test
{
  "prompt": true,
  "provider": "cli:claude"
}
