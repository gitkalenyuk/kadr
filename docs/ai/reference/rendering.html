Rendering commands

3 commands in the Rendering category. Each one works the same from the editor UI, REST, MCP and kadrctl.

  • render.devicesGPU devices
  • render.settings.getRender settings
  • render.settings.setChange render settings

render.devices

GPU devices

No undo stepSettings › RenderingMCP render_devices

Lists the graphics adapters Kadr can render on (Settings → Rendering → GPU): index, name, vendor (nvidia, amd, intel, apple), backend (vulkan, d3d12, metal), device type (discrete, integrated, cpu = software, virtual), total VRAM in MB, the OS budget for Kadr when known, driver, recommended (the high-performance default), supported (has the features Kadr needs; note explains why not), selected (used with the current settings) and effective_cap_mb (the VRAM Kadr would allow itself on that adapter: min(vram_limit_mb or total, total − reserve_mb, OS budget)). The same physical GPU can appear once per backend. available=false means no usable GPU or no wgpu library was found — Kadr then renders on the CPU (same picture, slower) and reason/hint explain it. Use an index or name from here with render.settings.set adapter. Read-only.

Parameters

No parameters.

Returns

{available, adapters[{index, name, vendor, backend, device_type, driver?, vram_total_mb, vram_budget_mb?, recommended, supported, note?, selected, effective_cap_mb}], selected (index into adapters, -1 = CPU), mode, reason?, hint?}.

Examples

Which GPUs can Kadr use?

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.devices \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run render.devices
// MCP tool: render_devices
{}

render.settings.get

Render settings

No undo stepSettings › RenderingMCP render_settings_get

Returns how Kadr renders previews and exports (Settings → Rendering): mode (auto = GPU when a working adapter exists, otherwise CPU; gpu = GPU only; cpu = always the CPU reference renderer) and where it came from (settings, or env when KADR_RENDER_MODE overrides it), the chosen adapter ("" = recommended), vram_limit_mb (0 = automatic) and reserve_mb (VRAM kept free for Windows/macOS and other apps, default 512), the resulting effective_cap_mb on the selected adapter (it covers Kadr's own process — the wgpu device, its memory blocks, textures, caches, frames in flight — plus the hardware video decoders, 256 MB each out of a quarter of the cap, and an export's hardware encoder, 256 MB; below 1 GB nothing is left for them and video is decoded and encoded in software; Kadr keeps the process's real video memory under its part of the cap and gives memory back to the OS when idle), the adapter's total VRAM, vram_used_mb (textures and buffers Kadr allocated), vram_process_mb (what the OS charges to Kadr's process on the GPU right now, 0 = unknown), and active — the renderer actually in use (kind gpu|cpu, backend, device, device_cap_mb for the process, hw_decoders, hw_encoders, idle when the device was released after a pause and is re-created on the next frame, and reason when the CPU is used). Example: a 12 GB card with vram_limit_mb 12288 gives an effective cap of 11776 MB. Read-only.

Parameters

No parameters.

Returns

{mode, mode_source settings|env, adapter, vram_limit_mb, reserve_mb, effective_cap_mb (0 = unknown), vram_total_mb, vram_budget_mb?, vram_used_mb, vram_process_mb, gpu_available, selected_adapter?{…render.devices entry}, active{kind, backend?, device?, vendor?, vram_total_mb?, cap_mb?, device_cap_mb?, hw_decoders?, hw_encoders?, used_mb, process_mb, idle?, reason?}, saved{mode, adapter, vram_limit_mb, reserve_mb}, note?, warning?}.

Examples

Current render settings

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.settings.get \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run render.settings.get
// MCP tool: render_settings_get
{}

render.settings.set

Change render settings

No undo stepChanges the systemSettings › RenderingMCP render_settings_set

Changes how Kadr renders and how much video memory it may use (Settings → Rendering) and saves it in settings.json "render". Only the given fields change. mode: auto (default; GPU when available, else CPU), gpu (refused when no usable GPU exists), cpu (always the CPU renderer). adapter: an index or name from render.devices (or a part of a name such as "RTX 3060"; numbers are indexes), "" = the recommended high-performance one. vram_limit_mb: how much VRAM Kadr may use, 0 = automatic (all of it minus reserve_mb); at least 256 and not more than the adapter's total VRAM (a round size like 12288 on a card the driver reports as 12115 MB is taken as "all of it"). reserve_mb: VRAM always left free for the system (default 512). The effective cap is min(vram_limit_mb or total, total − reserve_mb, OS budget): choosing 12288 on a 12 GB card leaves 512 MB for Windows and uses at most 11776 MB. Applies to the next frame or export, no restart; an export already running keeps its renderer. Picking a software adapter (device_type "cpu", e.g. Microsoft Basic Render Driver) is allowed for testing but returns a warning: it is many times slower than mode "cpu". App setting, not a project edit: not undoable. Calling it without changes returns the current settings with changed=false.

Parameters

ParameterTypeDescription
adapterstringGPU to use: index or name from render.devices (a part such as "RTX 3060" is enough; a plain number is an index); "" = the recommended adapter. Omit to keep.
modestring"auto" (GPU when available, otherwise CPU), "gpu" (GPU only) or "cpu" (CPU reference renderer). Omit to keep.
One of auto gpu cpu
reserve_mbintegerVRAM in MB always left free for the operating system and other apps; 0 = default 512. Unit: megabytes.
Range 0 … 65536
vram_limit_mbintegerMaximum VRAM Kadr may use in MB (1024 MB = 1 GB); 0 = automatic (total minus reserve_mb). At least 256 and at most the adapter's total VRAM. Unit: megabytes.
Range 0 … 1048576

Returns

Same as render.settings.get plus changed (always present; false when nothing changed) and warning (e.g. the GPU is unavailable so the settings apply once it is, the chosen adapter is a slow software renderer, or KADR_RENDER_MODE overrides the mode).

Examples

Let Kadr use 12 GB (keeps 512 MB for Windows)

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.settings.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"vram_limit_mb":12288}'
kadrctl run render.settings.set --vram_limit_mb 12288
// MCP tool: render_settings_set
{
  "vram_limit_mb": 12288
}

Use at most 6 GB

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.settings.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"vram_limit_mb":6144}'
kadrctl run render.settings.set --vram_limit_mb 6144
// MCP tool: render_settings_set
{
  "vram_limit_mb": 6144
}

Render on the CPU

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.settings.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"mode":"cpu"}'
kadrctl run render.settings.set --mode cpu
// MCP tool: render_settings_set
{
  "mode": "cpu"
}

Pick the RTX 3060, automatic VRAM

curl -X POST http://127.0.0.1:7777/api/v1/commands/render.settings.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"adapter":"RTX 3060","mode":"auto","vram_limit_mb":0}'
kadrctl run render.settings.set --adapter 'RTX 3060' --mode auto --vram_limit_mb 0
// MCP tool: render_settings_set
{
  "adapter": "RTX 3060",
  "mode": "auto",
  "vram_limit_mb": 0
}
