Best practices and pitfalls

Kadr’s commands are forgiving — every edit can be undone — but an agent that works in the right order gets better videos with fewer calls. These are the habits that matter most, and the traps that catch agents most often.

Read before you write

  • Start every session with project.list or project.get/timeline.get. Take ids from results — never construct or guess them.
  • Find library ids with library.list (kind: transition, effect, filter, animation, text_template, text_effect, text_animation, caption_style, sticker, font, generated, sound_effect, voice_effect) and check unknown parameters with kadrctl describe or the reference.
  • Look before you choose a look. Narrow candidates with category or query, then compare two or three with library.preview — a contact sheet of how each one plays — instead of picking by name. Fonts from font.catalog must be installed with font.install before text.update accepts their id. See Library, previews and fonts.
  • Re-read after edits that create or remove clips: splits, ai.remove_silence, ai.split_scenes, transcript cuts and magnet ripples change ids and times. Results usually list the new ids (segment_ids, left/right); otherwise call timeline.get again.

Plan, then batch

  • Group related edits into one kadr_batch (MCP), POST /projects/{id}/batch (REST) or kadrctl batch: they apply atomically, as one undo step, and the person watching sees one clean change.
  • Use dry_run to validate a big plan — it runs every call on a copy and reports the first failure without saving.
  • Work in phases: create things (and read their ids) → batch the follow-up edits. A batch cannot reference ids created inside the same batch.
  • Global commands (exports, captions jobs, project create/duplicate/delete, library, presets) cannot be batched.

Follow the error hints

Errors carry code, message, hint and often field. The hint is written for agents — it names the command that lists valid values or explains the rule that was broken:

{"name": "transition_set", "arguments": {"project_id": "prj_c0d7a4e19b5f", "segment_id": "seg_f8a1d3c6e204", "type": "mix"}}
kadrctl run transition.set --project_id prj_c0d7a4e19b5f --segment_id seg_f8a1d3c6e204 --type mix
error [conflict]: segment seg_f8a1d3c6e204 is the last clip on its track; a transition needs a following clip
hint: Transitions sit between two touching clips on the same track: pass the LEFT clip of the pair (the one that ends where the next one starts).
ErrorUsual causeWhat to do
not_found + fieldA stale or invented idRe-read with timeline.get / library.list
invalid_argumentWrong enum value, out-of-range number, seconds instead of µsThe message lists the allowed values; convert times to µs
conflictLocked track, clips that don’t touch (transitions), overlapping caption timesUnlock, move clips together, adjust neighbours first
not_available (HTTP 503)A missing local componentSee below; tell the person what to install
Result has clamped: trueThe request was limited (media end, half-clip transition, minimum length)Read the actual values in the result

Long jobs: wait or poll

  • Background jobs: captions.auto, transcript.transcribe, ai.remove_background, export.start. They return a job_id immediately.
  • wait: true (captions, transcription, background removal) blocks until done — fine for a few minutes of media, but MCP and kadrctl give up after 5 minutes.
  • For longer media, start without wait and long-poll captions.status with wait_s (up to 600 s per call); poll export.status every 1–2 s; or listen to captions.done/export.done events.
  • The first Whisper run loads the model and is slower. Exports run one at a time; extra jobs are queued. Jobs are forgotten when Kadr restarts.
kadrctl run captions.auto --project_id prj_c0d7a4e19b5f --language en --style_id cap_clean
kadrctl run captions.status --project_id prj_c0d7a4e19b5f --job_id cap_7e4b1a9d2c05 --wait_s 120
{"name": "captions_auto", "arguments": {"project_id": "prj_c0d7a4e19b5f", "language": "en", "style_id": "cap_clean"}}
{"name": "captions_status", "arguments": {"project_id": "prj_c0d7a4e19b5f", "job_id": "cap_7e4b1a9d2c05", "wait_s": 120}}

If something is missing, the hint says how to install it. Kadr never downloads models by itself; tell the person what to install instead of retrying.

Timeline traps

  • Don’t fight the magnet. On the main track at_us snaps to the nearest clip boundary and everything ripples. Build sequences in order, use overlay tracks for free placement, or switch the magnet off with timeline.settings.set.
  • Exact positions need snap: false on timeline.segment.move and timeline.segment.trim — otherwise an edge within 100 ms of a marker, the playhead or another edge jumps to it.
  • Keyframed properties: once a property has keyframes, segment.set_* writes a keyframe at the playhead. Edit animated values with keyframe.add at explicit times.
  • Transitions go on the left clip and need clips that touch; durations are capped at half the shorter clip.
  • Filters and effects on tracks affect everything below them — including text if the text track is lower. Add them before titles, or apply them to clips.
  • Units: times in µs; volume_db in dB but volume keyframes linear; positions in canvas fractions with +Y down; scale 1 = fit, not fill.

Files and paths

  • Paths are absolute and refer to the PC where Kadr runs. In JSON use forward slashes (C:/Users/you/Videos) or doubled backslashes.
  • A folder in media.import imports the media files directly inside it (not subfolders, up to 500); files already in the project are reported as duplicates.
  • Exports never overwrite unless overwrite is true — read the final path from the result. Without path they go to %USERPROFILE%\Videos\Kadr\<project name>.mp4.

Keep results small

  • timeline.get instead of project.get for orientation; segment.get for one clip in depth.
  • include_words: false on captions.list; include_words: false on transcript.get when you only need text.
  • Contact sheets of 8–12 tiles at 240–320 px; single frames at 960 px only when reading small text.

Respect the person

  • Open the project in the window (ui.open_project) and narrate phases with ui.toast — see Working visibly.
  • Make variants with project.duplicate instead of overwriting a finished edit; never project.delete without asking.
  • Don’t put the API token or cloud keys into prompts, files or logs; tts.set_api_key stores keys locally and never returns them.
  • Finish with a short report: what changed, where the export is, what you could not verify.
