REST API

Every Kadr command is available over HTTP on your own PC. POST a JSON object of arguments to /api/v1/commands/<name> and you get back exactly what the editor’s buttons get.

Base URL

http://127.0.0.1:7777/api/v1

The editor (Kadr.exe) and the headless kadr-server.exe both serve it. 7777 is only the default: the user can move the API in Settings → API & agents, an agent with app.api.set ({"port": 7790} — the window re-binds at once), and KADR_ADDR (for example 127.0.0.1:7790) overrides both for one process. Never hard-code the port in a script; find it like this:

  1. Read %APPDATA%\Kadr\api-endpoint.json (macOS ~/Library/Application Support/Kadr, Linux ~/.config/Kadr). Every running Kadr writes it and deletes it on exit: {"url": "http://127.0.0.1:7777", "pid": 12345, "version": "1.0.0", "token_file": "…\\api-token", "started_at": "…", "mode": "editor"}. Use url and the token in token_file when pid is alive.
  2. Otherwise settings.json → api.host/api.port, otherwise 127.0.0.1:7777.
  3. Or simply run kadrctl endpoint, which does all of this and prints the result; app.api.get returns the same from inside.
$ep  = Get-Content "$env:APPDATA\Kadr\api-endpoint.json" -Raw | ConvertFrom-Json
$env:KADR_TOKEN = (Get-Content $ep.token_file -Raw).Trim()
Invoke-RestMethod -Method Post -Uri "$($ep.url)/api/v1/commands/project.list" -Headers @{ Authorization = "Bearer $env:KADR_TOKEN" } -Body '{}'

The examples on this site use http://127.0.0.1:7777; replace it with your url. Without a token you can call GET /api/v1/health → {"ok":true,"result":{"status":"ok","version":"…"}}, GET /api/v1/openapi.json and the HTML reference at GET /docs.

Authentication

Everything else needs the API token, created on first run and stored in %APPDATA%\Kadr\api-token (Kadr shows the path in Settings → API & agents). Send it as a bearer token: Authorization: Bearer <token>.

$env:KADR_TOKEN = (Get-Content "$env:APPDATA\Kadr\api-token" -Raw).Trim()
set /p KADR_TOKEN=<"%APPDATA%\Kadr\api-token"
export KADR_TOKEN=$(cat "$APPDATA/Kadr/api-token")

Browsers cannot set headers on <img>, <audio> or WebSocket requests, so those may pass ?token=<token> instead. KADR_TOKEN set before Kadr starts overrides the file; to rotate the token, quit Kadr, delete api-token and start Kadr again.

Calling a command

POST /api/v1/commands/{name} with a JSON object of arguments (an empty body means no arguments). Names are the same everywhere — in the reference, in kadrctl, and in MCP with underscores.

curl -s http://127.0.0.1:7777/api/v1/commands/text.add -H "Authorization: Bearer $KADR_TOKEN" -d '{"project_id":"prj_a049124a748a","text":"Day one","template_id":"title_bold","at_us":0,"duration_us":2000000}'
kadrctl run text.add --project_id prj_a049124a748a --text "Day one" --template_id title_bold --at_us 0 --duration_us 2s
{"name": "text_add", "arguments": {"project_id": "prj_a049124a748a", "text": "Day one", "template_id": "title_bold", "at_us": 0, "duration_us": 2000000}}

In PowerShell, Invoke-RestMethod turns the answer into objects. Keep charset=utf-8 in the content type — without it Windows PowerShell 5.1 garbles non-English text.

function Invoke-Kadr($Command, $Arguments = @{}) {
  $body = $Arguments | ConvertTo-Json -Depth 10 -Compress
  $r = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:7777/api/v1/commands/$Command" `
    -Headers @{ Authorization = "Bearer $env:KADR_TOKEN" } `
    -ContentType 'application/json; charset=utf-8' -Body $body
  $r.result
}

$p = Invoke-Kadr project.create @{ name = 'Trip'; ratio = '9:16' }
Invoke-Kadr timeline.get @{ project_id = $p.id }

In Windows PowerShell 5.1, curl is an alias of Invoke-WebRequest; call curl.exe by its full name or use Invoke-RestMethod.

Response envelope

Every response is JSON. Success:

{ "ok": true, "result": { … the command’s result … } }

Failure — message says what went wrong, hint how to fix the call, field which parameter is at fault (when there is one):

{
  "ok": false,
  "error": {
    "code": "invalid_argument",
    "message": "parameter \"ratio\": must be one of [16:9 9:16 1:1 4:3 3:4 21:9 2.35:1 2:1 1.85:1 5.8-inch]",
    "hint": "Canvas aspect ratio. 9:16 is vertical (TikTok/Reels/Shorts), 16:9 is landscape (YouTube), 1:1 is square.",
    "field": "ratio"
  }
}

Error codes and HTTP status

CodeHTTPMeaning
invalid_argument400A parameter is missing, has the wrong type or is out of range; also a malformed batch.
unauthorized401Missing or wrong token.
forbidden403The request was not addressed to localhost/127.0.0.1/::1.
not_found404Unknown project, segment, material, job, voice or library id.
unknown_command404No command has that name.
conflict409The edit clashes with the project: a locked track, clips that don’t touch for a transition, overlapping cues.
nothing_to_undo409Undo or redo with an empty history.
not_implemented501The command is planned but not available yet.
not_available503Something needed is missing on this PC — FFmpeg, faster-whisper or a Whisper model, a speech voice, a matting model — or a cloud provider has no usable API key. The hint says what to install; tools.status, captions.asr_status, ai.capabilities and tts.voices report what was found.
internal500An unexpected failure (for example an FFmpeg error while rendering).

Times are microseconds

Every time and duration is an integer number of microseconds, and those parameters end in _us: one frame at 30 fps = 33333, 0.5 s = 500000, 1 min 30 s = 90000000. REST takes integers only; kadrctl also accepts 2.5s, 1500ms and 00:01:02.5. Other units are written in each parameter’s description (decibels, 0–1 opacity, canvas fractions…).

Discovering commands

RequestReturns
GET /api/v1/commandsEvery command spec: name, title, category, description, scope, params, returns, errors, examples, menu, undoable, read_only. ?category=Export filters.

Batches and dry runs

POST /api/v1/projects/{id}/batch runs several project commands as one atomic edit and one undo step (“Batch (N actions)”). If a call fails nothing is saved. With "dry_run": true every call runs on a copy and you see the results, but nothing is saved. project_id is filled in for every call.

[
  {"command": "segment.set_background", "args": {"segment_id": "seg_a049124a748b", "type": "blur", "blur": 0.75}},
  {"command": "text.add", "args": {"text": "Day one", "at_us": 0, "duration_us": 2000000}}
]
curl -s http://127.0.0.1:7777/api/v1/projects/prj_a049124a748a/batch -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"dry_run":false,"calls":[{"command":"segment.set_background","args":{"segment_id":"seg_a049124a748b","type":"blur","blur":0.75}},{"command":"text.add","args":{"text":"Day one","at_us":0,"duration_us":2000000}}]}'
kadrctl batch prj_a049124a748a demo.json --dry-run
kadrctl batch prj_a049124a748a demo.json
{"name": "kadr_batch", "arguments": {"project_id": "prj_a049124a748a", "calls": [
  {"command": "segment.set_background", "args": {"segment_id": "seg_a049124a748b", "type": "blur", "blur": 0.75}},
  {"command": "text.add", "args": {"text": "Day one", "at_us": 0, "duration_us": 2000000}}
]}}

The answer is {"ok": true, "result": {"results": [ … one per call … ], "dry_run": false}}. Calls run in order and see the effects of earlier calls, but arguments are fixed in advance, so a call cannot use an id created earlier in the same batch. Only project commands can be batched; global commands and edit.undo/edit.redo are rejected with invalid_argument (“call 0: …”, counting from 0).

Long-running jobs

Exports, auto captions, transcription and background removal return a job at once and run in the background. Poll export.status, captions.status (pass wait_s to long-poll up to 600 s) or ai.jobs — or listen to the events below. Jobs live in memory and are forgotten when Kadr restarts.

WebSocket events

Connect to ws://127.0.0.1:7777/api/v1/events?token=<token> to receive a JSON message whenever something happens — in the editor, through the API, from the CLI or from an agent. Add &project_id=prj_… to receive only that project’s events (plus events that belong to no project).

{
  "type": "project.changed",
  "project_id": "prj_1a347e3a7883",
  "source": "mcp",
  "data": { "commands": ["transition.apply_all"] },
  "time": "2026-10-01T16:47:42.9702474+02:00"
}

source is ui, api, mcp or cli, or the module that did background work (media, ai, tools, update).

A listener in Node.js 22+ (built-in WebSocket, no packages):

const token = require('fs').readFileSync(process.env.APPDATA + '/Kadr/api-token', 'utf8').trim();
const ws = new WebSocket('ws://127.0.0.1:7777/api/v1/events?token=' + token);
ws.onmessage = (m) => {
  const e = JSON.parse(m.data);
  if (e.type === 'export.progress') console.log(e.data.job_id, Math.round(e.data.progress * 100) + '%');
  else console.log(e.type, e.source, e.project_id || '');
};

Events say that something changed; read the new state with timeline.get. Slow clients lose events rather than slowing the editor down, so re-read state after a reconnect.

Security model

  • Local only. Kadr listens on 127.0.0.1; other computers cannot connect.
  • Host check. Requests must be addressed to localhost, 127.0.0.1 or ::1; anything else gets 403 forbidden. This blocks DNS-rebinding attacks from web pages.
  • Browser origins. CORS and WebSocket connections are accepted only from loopback origins, and the token is still required.
  • Token. Stored in your user profile; anyone who has it controls your projects. Never paste it into prompts or commit it.
  • Your files stay put. Commands read and write files at the paths you give, on the PC where Kadr runs.
