Застосунок: команди

3 команди у категорії «Застосунок». Кожна працює однаково з інтерфейсу редактора, через REST, MCP і kadrctl.

Описи команд і параметрів залишено англійською навмисно: це дослівно той самий текст, який ШІ-агенти отримують через MCP та OpenAPI, тож тут ви бачите саме те, що бачить агент. Решту сторінки перекладено.

  • app.api.getAPI address
  • app.api.setChange API address
  • app.versionAbout Kadr

app.api.get

API address

Без кроку скасуванняSettings › APIMCP app_api_get

Tells where this Kadr serves its local REST/WebSocket API (the same API kadrctl, kadr-mcp and AI agents use) — Settings → API. Returns the configured host and port, where they come from (source: env = the KADR_ADDR environment variable, settings = settings.json "api" saved by app.api.set, default = 127.0.0.1:7777), the URL clients should use right now, the token file that holds the Bearer token this API accepts, and the endpoint file (<data folder>/api-endpoint.json) that every running Kadr writes so tools find it automatically. listening=false or fallback=true means the configured port was busy: error and hint explain what holds it (another program, or another Kadr) and how to fix it. Read-only; never returns the token itself.

Параметри

Без параметрів.

Повертає

{host, port, url, docs, source env|settings|default, allow_remote, settings{host, port, allow_remote}, env_override?, token_file, endpoint_file, listening, listen_addr, fallback?, mode editor|headless, pid, error?, hint?, warning?}.

Приклади

Where is the API?

curl -X POST http://127.0.0.1:7777/api/v1/commands/app.api.get \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run app.api.get
// MCP tool: app_api_get
{}

app.api.set

Change API address

Без кроку скасуванняЗмінює системуSettings › APIMCP app_api_set

Changes the port (and optionally the host) of the local API and saves it in settings.json "api" — Settings → API → Port. The editor window moves the API immediately, without a restart: it binds the new port first (if that fails nothing changes and the error says why), then stops the old listener after this response is sent, rewrites <data folder>/api-endpoint.json and publishes app.api.changed. A headless kadr-server also moves live. kadrctl and kadr-mcp follow automatically because they read api-endpoint.json; scripts with a hard-coded address must use the returned url. The token does not change. Ports below 1024 are refused. host 127.0.0.1 (default) or localhost keep the API private to this computer; 0.0.0.0 exposes it to the network (token still required) and needs allow_remote=true. When KADR_ADDR is set it overrides the setting for this process: the value is saved but takes effect only when KADR_ADDR is removed (see warning). Calling it with the current values changes nothing. App setting, not a project edit: not undoable.

Параметри

ПараметрТипОпис
allow_remotebooleanConfirms exposing the API to other computers when host is 0.0.0.0. Anyone on the network who has the token can then control Kadr.
hoststringListen host: "127.0.0.1" (default, this computer only), "localhost", or "0.0.0.0" (all network interfaces; requires allow_remote=true). Omit to keep it.
Одне з 127.0.0.1 localhost 0.0.0.0
portintegerTCP port for the API, 1024..65535 (default 7777). Omit to keep the current port. Unit: port.
Діапазон 1024 … 65535

Повертає

Same as app.api.get plus changed (always present; false when nothing changed) and previous_url (set when it changed); warning explains a KADR_ADDR override or the risk of host 0.0.0.0.

Приклади

Move the API to port 7790

curl -X POST http://127.0.0.1:7777/api/v1/commands/app.api.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"port":7790}'
kadrctl run app.api.set --port 7790
// MCP tool: app_api_set
{
  "port": 7790
}

Back to the default address

curl -X POST http://127.0.0.1:7777/api/v1/commands/app.api.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"host":"127.0.0.1","port":7777}'
kadrctl run app.api.set --host 127.0.0.1 --port 7777
// MCP tool: app_api_set
{
  "host": "127.0.0.1",
  "port": 7777
}

Expose to the local network (careful)

curl -X POST http://127.0.0.1:7777/api/v1/commands/app.api.set \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"allow_remote":true,"host":"0.0.0.0"}'
kadrctl run app.api.set --allow_remote --host 0.0.0.0
// MCP tool: app_api_set
{
  "allow_remote": true,
  "host": "0.0.0.0"
}

app.version

About Kadr

Без кроку скасуванняSettings › AboutMCP app_version

Returns information about this Kadr installation — what the About section of Settings shows: the version (semver, e.g. 1.0.0; prerelease=true only for builds such as 1.1.0-beta.1), build details (git revision and time when available), Go version, OS and CPU architecture, the executable path, the data folder (projects, settings.json, api-token), whether it is a portable build, whether FFmpeg was found (path, version and where it came from), the active renderer with the current render settings (GPU adapter and backend, or the CPU fallback and why) and the GitHub repository used for updates (private: Kadr is distributed by invitation, see update.check). Use it to report bugs or to decide whether update.check / tools.install_ffmpeg are needed. Read-only and offline.

Параметри

Без параметрів.

Повертає

{name, version, prerelease, go_version, os, arch, build{module, vcs.revision?, vcs.time?, vcs.modified?}, executable, data_dir, portable, ffmpeg{found, ffmpeg_path, ffprobe_path, version, source, error}, update_repo, update_channel, update_signing_key, website, releases_url (private repository), changelog_url (public release notes), renderer{kind gpu|cpu, backend?, device?, vendor?, vram_total_mb?, vram_cap_mb?, vram_used_mb, reason? (why the CPU renders)} — the same shape as export.status renderer}.
