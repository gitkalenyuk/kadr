Експорт: команди

6 команд у категорії «Експорт». Кожна працює однаково з інтерфейсу редактора, через REST, MCP і kadrctl.

Описи команд і параметрів залишено англійською навмисно: це дослівно той самий текст, який ШІ-агенти отримують через MCP та OpenAPI, тож тут ви бачите саме те, що бачить агент. Решту сторінки перекладено.

export.cancel

Cancel export

Без кроку скасуванняExport dialog › CancelMCP export_cancel

Cancels a queued or running export — the Cancel button of the export progress view. A running job's FFmpeg process is killed and the partially written file is deleted; the call waits (up to 10 s) until the job has stopped and returns its final state "cancelled" (an export.cancelled event is published). Cancelling an already cancelled job is a no-op; cancelling a done or failed job returns conflict (delete the file yourself if needed).

Параметри

ПараметрТипОпис
job_idобов’язковийstringExport job id returned by export.start (e.g. "exp_1a2b3c4d5e6f"). export.list shows all known jobs.

Повертає

The job object (same shape as export.status), normally with state "cancelled".

Приклади

Stop an export

curl -X POST http://127.0.0.1:7777/api/v1/commands/export.cancel \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"job_id":"exp_1a2b3c4d5e6f"}'
kadrctl run export.cancel --job_id exp_1a2b3c4d5e6f
// MCP tool: export_cancel
{
  "job_id": "exp_1a2b3c4d5e6f"
}

export.estimate

Estimate export

Без кроку скасуванняMCP export_estimate

Resolves export settings without exporting: final width/height, frame rate, frame count, video bitrate, duration, estimated file size and the output path export.start would use right now (unique " (n)" name applied). Takes exactly the same parameters as export.start, so an agent can check the result first and the export dialog shows "Estimated size" from it. The size is bitrate × duration for video/audio (real files are usually a bit smaller with simple content) and a heuristic for GIF. encoder is the FFmpeg encoder that will be used (e.g. h264_nvenc, hevc_amf, h264_qsv, h264_videotoolbox or libx264; the encoder of the GPU Kadr renders on is preferred); it is empty until hardware detection has finished (it starts on the first call).

export.list

List exports

Без кроку скасуванняMCP export_list

Lists export jobs of this session, newest first — running and queued jobs as well as finished, failed and cancelled ones (the last 200 finished jobs are remembered; nothing survives a restart). Pass project_id to see only one project's exports, e.g. to find an export that is still running after the dialog was closed.

Параметри

ПараметрТипОпис

Повертає

Array of job objects (same shape as export.status).

export.start

Export

Ctrl+EБез кроку скасуванняTop bar › ExportMCP export_start

Starts exporting the project to a file in the background and returns immediately with a job_id — the Export button in the top bar. The project is snapshotted at this moment, so later edits do not change a running export. Every frame is rendered by the same compositor as the player and encoded with FFmpeg (H.264 or HEVC in MP4/MOV, 4:2:0 8-bit, BT.709 limited range, AAC 192 kbps stereo audio, +faststart for instant web playback). GPU rendering: when a GPU can be used (render.settings.get; NVIDIA, AMD, Intel via Vulkan/D3D12, Apple via Metal) every frame is composited on the GPU and handed to the encoder as NV12 without any CPU conversion; the hardware encoder of the same GPU (NVENC, AMF, Quick Sync, VideoToolbox) is used when it works (on an RTX 3060 a 1080p H.264 export of a real project runs at about 250 frames per second, roughly 6x the CPU renderer). The render.* settings apply: render.settings.set mode=cpu forces the CPU renderer, mode=gpu fails the export instead of falling back, and vram_limit_mb/reserve_mb cap the video memory Kadr uses (frames in flight, caches, the hardware decoders and the hardware encoder are sized from the cap; under 1024 MB the export decodes and encodes in software and says so in its warnings). If the GPU fails during the export (driver reset, device lost, out of video memory) the remaining frames are rendered on the CPU and the job finishes with a warning (export.status warnings; renderer.kind becomes "cpu"). Exports longer than 4 minutes are encoded in 2-minute parts joined at the end without re-encoding; an encoder that fails or stops responding (driver hiccup) is checked again and the export goes on from the part that failed, switching to the software encoder only when the hardware encoder fails its check (also with a warning; it is checked again before the next export). The soundtrack is mixed while the frames render. Set audio_only=true for an MP3/WAV/AAC/FLAC soundtrack, or gif=true for an animated GIF. Use range_start_us/range_end_us to export part of the timeline. Jobs run one at a time by default (others wait in state "queued"; KADR_EXPORT_CONCURRENCY raises it). Follow progress with export.status (poll every 1-2 s) or the export.progress / export.done / export.failed / export.cancelled / export.warning events; stop with export.cancel. Call export.estimate first to preview size and path. Does not modify the project and is not undoable. It is a global command (project_id is passed explicitly) so it cannot be part of a batch or dry run. Fails with invalid_argument when the timeline is empty.

export.status

Export status

Без кроку скасуванняMCP export_status

Returns the current state of one export job: state (queued, running, done, failed, cancelled), phase (starting, video, encoding, finalizing; audio only for audio-only exports), progress 0..1, frames_done/frames_total, speed_fps (frames encoded per second over the last few seconds), eta_s (seconds left from the frames left and that speed, -1 while unknown), elapsed_s, audio_progress (0..1, the soundtrack is mixed while the frames render), output path, size_bytes once done, the encoder used (e.g. h264_nvenc, hevc_amf, h264_videotoolbox or libx264), renderer {kind "gpu"|"cpu", backend (vulkan, d3d12, metal), device (adapter name), vendor, vram_total_mb, vram_cap_mb (the cap from render.settings), vram_used_mb (textures and buffers Kadr allocated), vram_process_mb (video memory the OS charges to Kadr's process now, kept under the cap), reason (why the CPU renders)}, warnings (problems the job recovered from: the GPU failed mid-export and the CPU finished it, an encoder failed or stopped responding and the export went on from the part that failed, the hardware encoder failed its check and the software encoder restarted the job, effects without a GPU version) and the error message on failure. Poll it every 1-2 seconds after export.start until state is terminal. Jobs are kept in memory only: after Kadr restarts the id is unknown (not_found), but finished files remain on disk.

ПараметрТипОпис
job_idобов’язковийstringExport job id returned by export.start (e.g. "exp_1a2b3c4d5e6f"). export.list shows all known jobs.

Повертає

{job_id, project_id, project_name, state, phase, progress, frames_done, frames_total, speed_fps, eta_s, elapsed_s, path, size_bytes, encoder, renderer {kind, backend, device, vendor, vram_total_mb, vram_cap_mb, vram_used_mb, vram_process_mb?, reason} (video/GIF jobs once rendering started), audio_progress, warnings[], error, settings, created_at, started_at, finished_at}.
