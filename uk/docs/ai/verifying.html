Перевірка результату

Успішна команда доводить лише те, що виклик був коректним. Щоб знати, що відео правильне, агент має робити те, що робить монтажер: прочитати таймлайн, подивитися на картинку, виміряти те, що можна виміряти, і нарешті перевірити експортований файл.

1. Прочитайте структуру

timeline.get — компактний вигляд «під агента»: доріжки згори донизу, кожен кліп із start_us, end_us, вихідним діапазоном, швидкістю, гучністю, групою зв’язку, переходом і ефектами, плюс duration_us усього монтажу й скільки разів використано кожен матеріал. Звірте з планом: правильний порядок, жодних несподіваних проміжків на немагнітних доріжках, загальна довжина як задумано.

kadrctl run timeline.get --project_id prj_e5a2c8f1d940
{"name": "timeline_get", "arguments": {"project_id": "prj_e5a2c8f1d940"}}

Щоб детально оглянути один кліп, segment.get з time_us повертає всі властивості плюс evaluated — значення ключових кадрів у цей момент.

2. Подивіться на картинку

preview.frame рендерить один кадр рендерером експорту. preview.contact_sheet рендерить сітку рівномірно розподілених кадрів (times_us — час кожної плитки); start_us/end_us наближають фрагмент. Через MCP обидва приходять як зображення, які бачить модель.

kadrctl run preview.frame --project_id prj_e5a2c8f1d940 --time_us 1s --width 960
kadrctl run preview.contact_sheet --project_id prj_e5a2c8f1d940 --count 8 --columns 4 --tile_width 240
{"name": "preview_frame", "arguments": {"project_id": "prj_e5a2c8f1d940", "time_us": 1000000, "width": 960}}
{"name": "preview_contact_sheet", "arguments": {"project_id": "prj_e5a2c8f1d940", "count": 8, "columns": 4, "tile_width": 240}}

Без MCP декодуйте png_base64 самі або візьміть JPEG з ендпоінта кадру:

$r = Invoke-Kadr preview.frame @{ project_id = 'prj_e5a2c8f1d940'; time_us = 1000000; width = 960 }
[IO.File]::WriteAllBytes("$PWD\frame.png", [Convert]::FromBase64String($r.png_base64))
Що шукатиДе
Чорні смуги чи краї під час наближеньКонтактний аркуш, потім кадри на початку й наприкінці руху
Обрізаний текст, перекриті субтитри, стікери на обличчяхКадри шириною 960 px і більше
Чорні кадри між кліпамиТемні плитки; проміжки в timeline.get
Слабкий перший кадр (мініатюра)preview.frame з time_us 0 або задайте обкладинку через project.set_cover

3. Виміряйте

preview.layout повертає рамку кожного видимого кліпу, тексту й стікера в заданий момент у пікселях полотна (x, y, w, h, rotation, corners, z). Кліп покриває кадр, коли x ≤ 0, y ≤ 0, x + w ≥ canvas_width і y + h ≥ canvas_height; текст уміщається, коли його рамка в цих межах.

kadrctl run preview.layout --project_id prj_e5a2c8f1d940 --time_us 1s
{"name": "preview_layout", "arguments": {"project_id": "prj_e5a2c8f1d940", "time_us": 1000000}}

Для звуку audio.loudness вимірює кліп (інтегральні LUFS, діапазон гучності, істинний пік і effective_lufs з урахуванням гучності кліпу). Мову під музикою добре чути, коли музика на 10–15 LU нижча. Для слів порівняйте captions.list (текст і час реплік) з transcript.get (що розпізнано).

4. Перевірте експортований файл

export.start одразу повертає job_id; опитуйте export.status кожні секунду-дві, доки state не стане done (або failed з error). Кінцевий path може відрізнятися від запитаного: наявний файл ніколи не перезаписується без overwrite, тож Kadr додає « (1)».

kadrctl run export.start --project_id prj_e5a2c8f1d940 --resolution 720p --path C:/Users/you/Videos/Kadr/check.mp4 --overwrite
kadrctl run export.status --job_id exp_2d7f9b1e4c06
{"name": "export_start", "arguments": {"project_id": "prj_e5a2c8f1d940", "resolution": "720p", "path": "C:/Users/you/Videos/Kadr/check.mp4", "overwrite": true}}
{"name": "export_status", "arguments": {"job_id": "exp_2d7f9b1e4c06"}}
{ "job_id": "exp_2d7f9b1e4c06", "state": "done", "progress": 1, "path": "C:\\Users\\you\\Videos\\Kadr\\check.mp4",
  "size_bytes": 117503, "encoder": "h264_nvenc", "settings": { "width": 1280, "height": 720, "fps": 30, "duration_us": 4000000, … } }

Потім підтвердьте сам файл. Якщо є оболонка, ffprobe відповість одним рядком. Якщо немає — Kadr сам може його проаналізувати: імпортуйте експорт у чернетковий проєкт (матеріал покаже тривалість, розмір, кодеки й наявність звуку), подивіться на нього й видаліть чернетковий проєкт (імпортовані файли ніколи не видаляються).

ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height -of compact "C:\Users\you\Videos\Kadr\check.mp4"
kadrctl run project.create --name "Scratch: check export" --ratio 16:9

Чекліст перед тим, як сказати «готово»

  • timeline.get: порядок, довжини й загальна тривалість відповідають плану.
  • Контактний аркуш усього монтажу плюс кадри в кожен ризикований момент (наближення, титри, перший кадр).
  • preview.layout підтверджує покриття кадру й те, що текст уміщається; audio.loudness — баланс голосу й музики.
  • Субтитри відповідають сценарію (captions.list); виправлення зроблено через captions.update.
  • export.status — done; тривалість, розмір і звук файлу підтверджено.
  • Короткий звіт людині: що змінено, де файл, у чому ви не були певні.
