Вбудований ШІ-асистент

У редакторі Kadr є ШІ-асистент (кнопка AI, Ctrl+Shift+A). Він керує Kadr через той самий реєстр команд, що й будь-який інший агент, з двома видами бекендів: CLI-агенти для програмування, встановлені на ПК, і вбудований цикл агента через LLM API. Ця сторінка пояснює, як він працює, — знадобиться, якщо вас запустив він, якщо ви керуєте ним через API або додаєте команди, з якими він має поводитися обережно. Як ним користуються люди — у посібнику.

Системний промпт містить ті самі домовленості, що й Концепції, плюс поточний контекст: проєкт, курсор відтворення, виділення, режим дозволів і сьогоднішню дату. Довгі чати підсумовуються автоматично; старі результати інструментів скорочуються, а в контексті лишаються лише кілька останніх зображень.

Як запускається CLI-агент

  • Без інтерфейсу, у власній робочій папці (типово %TEMP%\kadr-agents\<agent>-<chat>), сталій для чату, щоб власний сеанс CLI можна було продовжити наступним повідомленням.
  • MCP-сервер Kadr підключається лише на цей запуск, ніколи — у глобальні налаштування користувача: прапорцем (Claude Code --mcp-config + --strict-mcp-config, Codex -c mcp_servers.kadr.*, Copilot --additional-mcp-config, Qwen --mcp-config), змінною середовища з тимчасовим файлом (Amp, Cline, OpenCode) або локальним файлом проєкту в робочій папці (Gemini CLI, Cursor, Antigravity, Kimi, Crush, Droid).
  • Два транспорти, один фільтр. Кожен запуск відкриває власний MCP-сервер усередині Kadr (gateway) на 127.0.0.1 з випадковим секретним шляхом; він питає фільтр дозволів перед кожним викликом, тож картки схвалення працюють навіть для CLI без власного механізму дозволів у фоновому режимі. gateway-CLI підключаються до нього через HTTP; stdio-CLI запускають kadr-mcp --gateway <url> — простий міст до того самого сервера, який ніколи не звертається до REST API напряму (Kadr бере лише kadr-mcp, що підтримує цей режим), тож жоден CLI-агент не дістається інструментів Kadr в обхід фільтра. Claude Code і Cline ще й перетворюють власні запити дозволу (зокрема дії оболонки й файлів) на картки схвалення.
  • Вбудовані інструменти оболонки, файлів і вебу вимкнені або заборонені типово — власним механізмом кожного CLI. Перемикач чату Allow actions outside Kadr їх вмикає (з запитанням, якщо чат не в режимі full auto). CLI, які так обмежити неможливо (Kimi Code, Warp), запускаються лише з цим перемикачем.
  • Ключі для CLI беруться зі сховища й передаються лише через його змінні середовища — ніколи в аргументах, файлах чи подіях. Кожен рядок виводу проходить через фільтр, що маскує секрети.
  • Stop завершує все дерево процесів (у Windows агент працює в Job-об’єкті, тож нічого не лишається).

Список інструментів для кожного агента. Кожна команда як окремий інструмент — це близько 200 інструментів і приблизно 400 КБ описів і схем у кожному ході, більше, ніж приймають деякі моделі. Тому CLI-агенти за замовчуванням отримують п'ять метаінструментів (близько 4 КБ): вони шукають команди в реєстрі, читають документацію команди й запускають команди. kadr_run і kadr_preview_frame розгортаються до перевірки дозволів, тож картки підтвердження називають справжню команду. Claude Code лишається з повним списком. assistant.settings.set {"cli_tools": {"codex": "full"}} перемикає одного агента (Settings → AI assistant → агент → Kadr tools), а "" повертає його типовий режим. Власний агент обирає це полем tools у своїй специфікації.

Фільтр дозволів

Кожен виклик асистента — через метаінструмент, gateway чи власний запит дозволу CLI — класифікується до виконання. Режим чату визначає, що потребує картки схвалення:

Клас береться з поля risk у специфікації команди (paid, delete, overwrite, system, secret — те саме значення зовнішні агенти бачать як risk у GET /api/v1/commands, x-risk в OpenAPI і рядок Risk: в описі кожного MCP-інструмента) плюс правила для викликів, ризик яких залежить від аргументів (експорт поверх наявного файлу, хмарний голос, виклик із ключем). Для платних викликів фільтр запускає відповідну <namespace>.estimate, щоб показати вартість, і після схвалення сам підставляє її confirm_token — агент усередині асистента ніколи не має справи з токенами. «Always for this chat» запам’ятовує схвалення для команди (ніколи для платних). Картки без відповіді відхиляються через 10 хвилин; відхилену дію не можна повторювати.

Керування асистентом із коду

# що може його «живити»
curl -s http://127.0.0.1:7777/api/v1/commands/assistant.providers -H "Authorization: Bearer $KADR_TOKEN" -d '{}'
# надіслати повідомлення й дочекатися всього ходу
curl -s http://127.0.0.1:7777/api/v1/commands/assistant.send -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"project_id":"prj_1a2b3c4d5e6f","provider":"api:anthropic","text":"Add a title \"Day 1\" for the first 3 seconds","wait":true}'
# відповісти на картку схвалення (з події assistant.approval_request)
curl -s http://127.0.0.1:7777/api/v1/commands/assistant.approve -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"session_id":"ses_0a1b2c3d4e5f","request_id":"perm_1a2b3c4d","decision":"allow"}'
# скасувати все, що зробив чат (один крок скасування)
curl -s http://127.0.0.1:7777/api/v1/commands/assistant.revert -H "Authorization: Bearer $KADR_TOKEN" -d '{"project_id":"prj_1a2b3c4d5e6f","session_id":"ses_0a1b2c3d4e5f"}'
kadrctl run assistant.providers
kadrctl run assistant.send --project_id prj_1a2b3c4d5e6f --provider api:anthropic --text "Add a title \"Day 1\" for the first 3 seconds" --wait
kadrctl run assistant.approve --session_id ses_0a1b2c3d4e5f --request_id perm_1a2b3c4d --decision allow
kadrctl run assistant.revert --project_id prj_1a2b3c4d5e6f --session_id ses_0a1b2c3d4e5f
  • assistant.send одразу повертає session_id і run_id (або, з wait, фінальну відповідь, використання токенів і вартість). Без session_id починає новий чат; перше повідомлення зберігає контрольну точку для assistant.revert. Вкладення: абсолютні шляхи, вставлені дані (data_base64), текст, material_id, segment_id чи time_us.
  • Живі події у WebSocket (/api/v1/events): assistant.message.delta, assistant.message, assistant.thinking, assistant.tool_call, assistant.tool_result, assistant.approval_request, assistant.approval_resolved, assistant.usage, assistant.status, assistant.error, assistant.done. assistant.session повертає збережений чат тими самими подіями, тож один редуктор відображає обидва випадки.
  • assistant.stop завершує хід; assistant.revert падає з conflict, якщо проєкт хтось змінив після контрольної точки, — хіба що force: true; спершу спитайте користувача.
  • Зміни асистента мають джерело assistant в історії скасування й у подіях project.changed.
  • Чати зберігаються в папці проєкту (assistant/sessions/), ніколи не експортуються й видаляються разом із проєктом; assistant.sessions показує їх із вартістю й кількістю змін.

Якщо ви додаєте команди в Kadr

Задайте Risk у новій command.Spec, якщо команда витрачає гроші (paid, і додайте <namespace>.estimate, що повертає confirm_token), видаляє з диска (delete), може перезаписати файл поза проєктом (overwrite), змінює інсталяцію чи машину (system) або приймає облікові дані (secret). Звичайним змінам зі скасуванням нічого не треба: асистент у типовому режимі виконує їх вільно, і їх можна відкотити.
