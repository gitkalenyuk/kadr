Any client that can start a local stdio MCP server can drive Kadr. The server is a single executable with no arguments; everything else is optional.

The settings every client needs

SettingValue
Transportstdio
CommandFull path to kadr-mcp.exe (or kadr-mcp when it is on PATH), no arguments
EnvironmentOptional: KADR_ADDR, KADR_DATA_DIR, KADR_TOKEN
Protocol version2025-06-18
Tools178: one per command plus kadr_batch; read-only commands carry readOnlyHint, project_delete carries destructiveHint

When the engine is not running, kadr-mcp starts kadr-server.exe from its own folder and waits up to 10 seconds for it. It reads the API token from the Kadr data folder, so no secret goes into the client’s config.

Config snippets

The file names and shapes below are what these clients use at the time of writing — check your client’s documentation if a key has changed. Comments are for orientation; remove them if your client rejects comments in JSON.

// %USERPROFILE%\.cursor\mcp.json (all projects) or .cursor\mcp.json (one project)
{
  "mcpServers": {
    "kadr": { "command": "C:\\Users\\you\\AppData\\Local\\Programs\\Kadr\\kadr-mcp.exe" }
  }
}
// .vscode\mcp.json (VS Code agent mode)
{
  "servers": {
    "kadr": { "type": "stdio", "command": "C:\\Users\\you\\AppData\\Local\\Programs\\Kadr\\kadr-mcp.exe" }
  }
}
// %USERPROFILE%\.codeium\windsurf\mcp_config.json
{
  "mcpServers": {
    "kadr": { "command": "C:\\Users\\you\\AppData\\Local\\Programs\\Kadr\\kadr-mcp.exe" }
  }
}
# %USERPROFILE%\.codex\config.toml (Codex CLI)
[mcp_servers.kadr]
command = 'C:\Users\you\AppData\Local\Programs\Kadr\kadr-mcp.exe'
// %USERPROFILE%\.gemini\settings.json (Gemini CLI)
{
  "mcpServers": {

  }
}

Test the bridge by hand

MCP over stdio is one JSON-RPC message per line, so PowerShell can talk to the bridge directly — useful when a client only says “failed to start”:

@'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"test","version":"1"}}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"project_list","arguments":{}}}
'@ | & "$env:LOCALAPPDATA\Programs\Kadr\kadr-mcp.exe"

The second line of output is the project_list result. Errors come back as tool results with "isError": true and the engine’s JSON error (code, message, hint, field), so agents can read the hint and retry.

Agents without MCP

  • Function calling. Generate tool definitions from openapi.json (each command’s request body is a JSON Schema) and execute calls with POST /api/v1/commands/<name> — see REST API.
  • Shell-only agents. Let the agent run kadrctl describe <command> to read documentation and kadrctl run to execute — see kadrctl.
  • Context. Give the model llms.txt or the complete llms-full.txt.

Kadr on another machine

The API only accepts requests addressed to localhost, by design. To drive Kadr on another PC, forward a local port to it (for example ssh -L 7777:127.0.0.1:7777 user@editing-pc), copy that PC’s api-token into KADR_TOKEN, and keep in mind that file paths refer to the remote disk.
