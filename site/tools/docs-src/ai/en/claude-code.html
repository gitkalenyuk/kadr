One command registers Kadr’s MCP server with Claude Code for every project on your PC. After that, describe the video you want — Claude edits it in Kadr, looks at rendered frames to check its work, and every change can be undone.

Before you start

  • Kadr is installed. The installer puts kadr-mcp.exe in %LOCALAPPDATA%\Programs\Kadr\ next to Kadr.exe and kadr-server.exe. In Kadr, Settings → API & automation shows the exact path and a ready-made command.
  • Claude Code is installed and claude runs in your terminal.
  • Kadr does not have to be running. If neither the editor nor a server answers, kadr-mcp starts the headless kadr-server.exe by itself (about 2 seconds). To watch the edits, open Kadr before the first call — see the note below.

1. Add the server

Register Kadr once for your user account (--scope user), so it is available in every folder. Everything after -- is the command Claude Code starts.

claude mcp add --scope user kadr -- "%LOCALAPPDATA%\Programs\Kadr\kadr-mcp.exe"
claude mcp add --scope user kadr -- "$env:LOCALAPPDATA\Programs\Kadr\kadr-mcp.exe"

If you kept the installer option Add kadrctl and kadr-mcp to PATH, the short form works too: claude mcp add --scope user kadr -- kadr-mcp.

2. Check the connection

claude mcp list
claude mcp get kadr

kadr should be listed as connected. Inside a session, /mcp shows the server, its 178 tools (one per command plus kadr_batch) and lets you reconnect after a problem.

3. Pre-approve tools (optional)

Claude Code asks before it uses a tool. To stop the prompts for Kadr, allow the whole server in .claude/settings.json (one project) or ~/.claude/settings.json (everywhere):

{
  "permissions": {
    "allow": ["mcp__kadr"]
  }
}

Prefer something stricter? Allow only read-only tools, for example "mcp__kadr__project_list", "mcp__kadr__timeline_get", "mcp__kadr__preview_frame" and "mcp__kadr__preview_contact_sheet", and keep approving edits one by one. Every edit can be undone anyway.

4. First prompts to try

Open Kadr first so you can watch, start claude in any folder, and try:

List my Kadr projects and summarise the timeline of the most recent one.

Create a 9:16 Kadr project called "MCP test", generate a 5-second aurora_flow background, add the title "It works" with the title_bold template, open the project in the Kadr window and show me the frame at 1 second.

Import C:\Users\you\Videos\clip.mp4 into "MCP test", put it after the background, add word-highlight captions and show me a contact sheet of the whole video.

Put a 0.4-second mix transition on every cut in one batch, then export 1080p to C:\Users\you\Videos\Kadr\mcp-test.mp4 and tell me when it is done.

Undo the last two changes in "MCP test".

More complete workflows, with every call spelled out, are in the recipes.

Watching live needs the editor’s engine. If Kadr was closed when Claude made its first call, kadr-mcp started a headless kadr-server.exe, which keeps running after the chat. If you then open Kadr, the window cannot take over port 7777 and will not show the agent’s edits. Quit kadr-server.exe (Task Manager → Details) before opening Kadr, then run /mcp to reconnect.

Share the setup with a repository

For a folder that always works with Kadr, commit a .mcp.json at its root. Claude Code asks each person once before it loads a project-scoped server. With kadr-mcp on PATH the file is the same for everyone:

{
  "mcpServers": {
    "kadr": { "type": "stdio", "command": "kadr-mcp", "args": [] }
  }
}

A few lines in that folder’s CLAUDE.md save the agent a lot of guessing:

## Video editing
- Edit videos through the kadr MCP server. Times are integer microseconds (1 s = 1000000).
- Read state first (timeline_get), apply related edits in one kadr_batch, then check with preview_frame or preview_contact_sheet.
- Show your work: call ui_open_project at the start; export with export_start and poll export_status.
- Media lives in ./footage; exports go to ./exports.

A different port or data folder

To drive a separate engine (for example a test kadr-server.exe on port 7790 with its own projects), pass environment variables when adding the server:

claude mcp add --scope user --env KADR_ADDR=127.0.0.1:7790 --env KADR_DATA_DIR=D:\kadr-automation kadr-test -- "$env:LOCALAPPDATA\Programs\Kadr\kadr-mcp.exe"

Remove a server with claude mcp remove kadr --scope user.

Tips for Claude Code

  • Large results. Claude Code caps a tool result at about 25,000 tokens by default (MAX_MCP_OUTPUT_TOKENS raises it). Prefer timeline_get over project_get, pass include_words: false to captions_list, and keep contact-sheet tiles small (240–320 px).
  • Long jobs. Captions, transcription and exports run in the background. Asking for wait: true is fine for a few minutes of media; for longer jobs ask Claude to poll captions_status (with wait_s) or export_status.
  • Slow first start. If the server times out while the engine starts, raise MCP_TIMEOUT (milliseconds) when launching Claude Code.
  • Files. Paths are on the PC where Kadr runs. Claude Code’s own file tools and Kadr see the same disk, so Claude can write a batch file or an SRT and hand its path to Kadr.

Troubleshooting

SymptomFix
claude mcp list shows kadr as failedCheck the path: Test-Path "$env:LOCALAPPDATA\Programs\Kadr\kadr-mcp.exe". Quote paths that contain spaces.
Kadr engine did not start … within 10 skadr-server.exe must sit next to kadr-mcp.exe. Start Kadr yourself, then /mcp → reconnect.
unauthorized: missing or invalid API tokenA stale KADR_TOKEN or a different KADR_DATA_DIR in the server’s environment. Remove them, or re-add the server.
Edits don’t appear in the open windowA headless kadr-server.exe owns port 7777 — see the warning above.
not_available from captions or background removalAn optional local component is missing. Ask Claude to run captions_asr_status or ai_capabilities; the hint says what to install.
