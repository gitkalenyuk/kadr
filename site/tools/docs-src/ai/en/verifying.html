A command that succeeded only proves the call was valid. To know the video is right, an agent should do what an editor does: read the timeline, look at the picture, measure what can be measured, and finally check the exported file.

1. Read the structure

timeline.get is the compact, agent-sized view: tracks top to bottom, each clip with start_us, end_us, source range, speed, volume, link group, transition and effects, plus duration_us of the whole edit and how often each material is used. Compare it with the plan: right order, no unexpected gaps on non-magnetic tracks, total length as intended.

kadrctl run timeline.get --project_id prj_e5a2c8f1d940
{"name": "timeline_get", "arguments": {"project_id": "prj_e5a2c8f1d940"}}

For one clip in depth, segment.get with time_us returns every property plus evaluated — the keyframed values at that moment.

2. Look at the picture

preview.frame renders one frame with the export renderer. preview.contact_sheet renders a grid of evenly spaced frames (times_us lists each tile’s time); start_us/end_us zoom in on a section. Through MCP both arrive as images the model can see.

kadrctl run preview.frame --project_id prj_e5a2c8f1d940 --time_us 1s --width 960
kadrctl run preview.contact_sheet --project_id prj_e5a2c8f1d940 --count 8 --columns 4 --tile_width 240
{"name": "preview_frame", "arguments": {"project_id": "prj_e5a2c8f1d940", "time_us": 1000000, "width": 960}}
{"name": "preview_contact_sheet", "arguments": {"project_id": "prj_e5a2c8f1d940", "count": 8, "columns": 4, "tile_width": 240}}

Without MCP, decode png_base64 yourself, or fetch a JPEG from the frame endpoint:

$r = Invoke-Kadr preview.frame @{ project_id = 'prj_e5a2c8f1d940'; time_us = 1000000; width = 960 }
[IO.File]::WriteAllBytes("$PWD\frame.png", [Convert]::FromBase64String($r.png_base64))

3. Measure

preview.layout returns the box of every visible clip, text and sticker at a time, in canvas pixels (x, y, w, h, rotation, corners, z). A clip covers the frame when x ≤ 0, y ≤ 0, x + w ≥ canvas_width and y + h ≥ canvas_height; text fits when its box is inside those bounds.

kadrctl run preview.layout --project_id prj_e5a2c8f1d940 --time_us 1s
{"name": "preview_layout", "arguments": {"project_id": "prj_e5a2c8f1d940", "time_us": 1000000}}

For sound, audio.loudness measures a clip (integrated LUFS, loudness range, true peak, and effective_lufs including the clip’s volume). Speech under music reads well when the music sits 10–15 LU lower. For words, compare captions.list (cue text and times) with transcript.get (what was recognised).

4. Check the exported file

export.start returns a job_id immediately; poll export.status every second or two until state is done (or failed with an error). The final path can differ from the one you asked for: an existing file is never overwritten unless you pass overwrite, so Kadr adds “ (1)”.

kadrctl run export.start --project_id prj_e5a2c8f1d940 --resolution 720p --path C:/Users/you/Videos/Kadr/check.mp4 --overwrite

Then confirm the file itself. With a shell, ffprobe answers in one line. Without one, Kadr can probe it: import the export into a scratch project — the material reports duration, size, codecs and whether it has sound — look at it, and delete the scratch project (imported files are never deleted).

ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height -of compact "C:\Users\you\Videos\Kadr\check.mp4"
kadrctl run project.create --name "Scratch: check export" --ratio 16:9

Checklist before saying “done”

  • timeline.get: order, lengths and total duration match the plan.
  • A contact sheet of the whole edit, plus frames at every risky moment (zooms, titles, the first frame).
  • preview.layout confirms coverage and that text fits; audio.loudness confirms voice vs. music.
  • Captions match the script (captions.list); fixes made with captions.update.
  • export.status is done; the file’s duration, size and audio are confirmed.
  • A short report to the person: what changed, where the file is, anything you were unsure about.
