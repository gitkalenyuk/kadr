kadrctl runs any Kadr command from a terminal. It reads each command’s parameters from the running engine, converts values to the right types (including times like 2.5s), and prints the result as JSON — handy for quick edits, for scripts, and for agents that only have a shell.

Setup

kadrctl.exe is installed next to Kadr.exe in %LOCALAPPDATA%\Programs\Kadr\. With the installer option Add kadrctl and kadr-mcp to PATH (on by default) it works from any new terminal: kadrctl help, kadrctl version.

Unlike kadr-mcp, kadrctl does not start the engine: Kadr or kadr-server.exe must be running. It finds the address and token in %APPDATA%\Kadr by itself.

Writing parameters

Each parameter becomes a flag with the same name; kadrctl converts the value to the parameter’s type. Unknown flags are rejected before anything runs.

FormExampleNotes
--param value, --param=value--ratio 9:16Quote values with spaces: --name "Kitchen tour".
Boolean--wait, --wait true, --snap falseA bare flag means true.
Number--volume_db -12, --scale 0.6Negative numbers are fine.
Time (*_us)2500000, 2.5s, 1500ms, 1m2s, 00:01:02.5Converted to microseconds; a plain number already is microseconds.
Array or object--paths "[\"C:/Clips\"]"Must be JSON — see quoting.

Quoting JSON on Windows

Array and object parameters (paths, segment_ids, style, params, points…) are JSON, and its double quotes must survive the shell:

ShellWrite
Command Prompt--paths "[\"C:/Users/you/Videos/trip\"]"
PowerShell 7.3+--paths '["C:/Users/you/Videos/trip"]'
Windows PowerShell 5.1--paths '[\"C:/Users/you/Videos/trip\"]'
Any PowerShellkadrctl --% run media.import --project_id prj_… --paths "[\"C:/Users/you/Videos/trip\"]"

The docs use the --% form: it works in every PowerShell version, and without --% the same line works in Command Prompt. After --% PowerShell stops interpreting the line, so $variables are not expanded. Inside JSON use forward slashes in paths (C:/Users/you) or double backslashes. In PowerShell, quote colours ("#FFD400" — # starts a comment) and put text containing $ in single quotes.

Batch files

A batch file is a JSON array of {command, args} objects without project_id (it comes from the command line). --dry-run checks the batch on a copy without saving. Save the file as UTF-8 without a byte-order mark: kadrctl rejects a BOM, and Windows PowerShell 5.1’s Set-Content -Encoding UTF8 writes one — use [IO.File]::WriteAllText() as in the script below.

[
  { "command": "transition.apply_all", "args": { "type": "mix", "duration_us": 400000 } },
  { "command": "text.add", "args": { "text": "Kitchen tour", "template_id": "title_bold", "at_us": 0, "duration_us": 2500000 } }
]
kadrctl batch prj_9d2e4c7a1b05 calls.json --dry-run
kadrctl batch prj_9d2e4c7a1b05 calls.json

Scripting in PowerShell

This script makes a vertical, reframed short from every .mp4 in a folder and queues the exports. It runs in Windows PowerShell 5.1 and PowerShell 7. The helper kadr turns kadrctl’s JSON into objects and stops on errors; kadr-batch sends JSON through a file, so paths with spaces need no quoting.

$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [Text.Encoding]::UTF8   # read non-English names correctly

# Run kadrctl and turn its JSON output into PowerShell objects.
function kadr {
  $out = kadrctl @args
  if ($LASTEXITCODE -ne 0) { throw "kadrctl $($args[0]) $($args[1]) failed" }
  $out | Out-String | ConvertFrom-Json
}

# Run calls as one batch. JSON goes through a file, so no shell quoting is involved.
function kadr-batch($ProjectId, $Calls) {
  $file = Join-Path $env:TEMP 'kadr-calls.json'
  [IO.File]::WriteAllText($file, (ConvertTo-Json -InputObject @($Calls) -Depth 10))  # UTF-8, no BOM
  kadr batch $ProjectId $file
}

$src = "$env:USERPROFILE\Videos\Raw"
$dst = "$env:USERPROFILE\Videos\Kadr\Shorts"

Get-ChildItem $src -Filter *.mp4 | ForEach-Object {
  $p   = kadr run project.create --name $_.BaseName --ratio 9:16
  $imp = kadr-batch $p.id @(@{ command = 'media.import'; args = @{ paths = @($_.FullName) } })
  $seg = kadr run timeline.segment.add --project_id $p.id --material_id $imp.results[0].materials[0].id
  kadr run ai.auto_reframe --project_id $p.id --segment_id $seg.segment.id --ratio 9:16 | Out-Null
  $job = kadr run export.start --project_id $p.id --resolution 1080p --path "$dst\$($_.BaseName).mp4"
  "{0} -> {1} ({2})" -f $_.Name, $job.path, $job.state
}

kadr run export.list | Format-Table job_id, state, progress, path
  • Exports run one at a time; extra jobs wait as queued, so the loop finishes long before the videos do.
  • export.estimate shows the final size and path without exporting.
  • To test a script safely, point it at a separate engine: $env:KADR_DATA_DIR and $env:KADR_ADDR for both kadr-server.exe and kadrctl.

Exit codes and errors

On success kadrctl prints the result to standard output and exits with 0. On failure it prints the error to standard error and exits with 1:

error [not_found]: project "prj_nope" not found
hint: Call project.list to get valid project ids.

Problems found before the call is sent start with a plain error::

error: project.list has no parameter "foo" (see `kadrctl describe project.list`)
error: cannot reach Kadr at http://127.0.0.1:7777 (is the editor or `kadr-server` running?): …

Error codes are the same as in the REST API.
