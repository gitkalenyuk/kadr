Every edit an agent makes appears in the open Kadr window immediately. The ui.* commands go one step further: they steer what the window shows — which project, which clip, which library tab — and put short notes on screen, so a person can follow along, learn, and step in.

When the window can follow

  • The agent must be talking to the editor (Kadr.exe), not to a headless kadr-server.exe. app.version tells which: its executable ends in Kadr.exe for the editor.
  • ui.* commands change no project data, are not undoable, and simply do nothing when no window is open — they are always safe to call.
  • Edits from the agent and from the person land in one undo history. The person can press Ctrl+Z on any agent edit; an agent can edit.undo a human edit.

The commands

CommandWhat the person sees
ui.open_projectThe window switches to that project, as if it was opened from Home.
ui.selectA clip is selected on the timeline and its properties appear in the inspector. segment_id "" clears the selection.
ui.library_tabThe left panel switches to media, audio, text, stickers, effects, transitions, captions, transcript, filters, adjustment or templates (My kit).
ui.toastA short notification at the top of the window: a bold title and an optional body.
playback.seek, playback.play, playback.pauseThe playhead moves and the player shows that frame, or plays from there.

A narrated edit

Open the project, announce the step, show where the feature lives, select the clip, make the edit, then play the result:

kadrctl run ui.open_project --project_id prj_6b0e4d2a9c71
kadrctl run ui.toast --title "Adding a transition" --body "Cube turn between the two shots"
kadrctl run ui.library_tab --tab transitions
kadrctl run ui.select --project_id prj_6b0e4d2a9c71 --segment_id seg_d02f7b9e3a64
kadrctl run transition.set --project_id prj_6b0e4d2a9c71 --segment_id seg_d02f7b9e3a64 --type cube_turn_left --duration_us 0.6s
kadrctl run playback.play --project_id prj_6b0e4d2a9c71 --from_us 2s
kadrctl run playback.pause --project_id prj_6b0e4d2a9c71
kadrctl run ui.select --project_id prj_6b0e4d2a9c71 --segment_id=

Good habits

  • Open the project first. Call ui.open_project right after creating or choosing a project, before the edits start.
  • Narrate phases, not calls. One toast per meaningful step (“Cutting to the beat”, “Adding captions — about a minute”) is enough; dozens of toasts are noise.
  • Batch visual edits. A kadr_batch lands as one update and one undo step, so the person sees a clean change instead of flicker.
  • Point at what changed. ui.select the clip and playback.seek to the moment you edited, so the player shows it.
  • Ask before big moves. If the person is editing at the same time, agree who edits what: every command is atomic, but there is no locking between people and agents.
  • Long jobs. Toast when a caption job or an export starts and when it ends; the window also shows export progress itself.

Under the hood

The ui.* commands publish ui.open_project, ui.select, ui.library_tab and ui.toast events. Every open window — the desktop app or the editor in web mode — follows them, and any other client can see them on the event stream.
