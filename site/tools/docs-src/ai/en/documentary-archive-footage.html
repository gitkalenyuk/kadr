You get a 30-second documentary about D-Day, 6 June 1944, cut from public-domain newsreels: five archive shots, each timed to a line of Ukrainian narration read by an ElevenLabs voice, slow Ken Burns moves, a black-and-white film-strip look, an opening title, corrected Ukrainian captions and a source credit. The same steps work for any topic and any language.

  • Time: ~10 min (mostly downloading)
  • You need: ffmpeg on PATH, an ElevenLabs API key (optional — local voices work too), internet for the footage
  • Main commands: media.import, tts.set_api_key, tts.voices, tts.speak, timeline.segment.add, timeline.segment.trim, keyframe.add, transition.apply_all, filter.add, effect.add, captions.auto, captions.update, ui.open_project, export.start

Ask Claude

Make a 30-second Ukrainian-language documentary about D-Day (6 June 1944) in Kadr. Find public-domain newsreel footage on archive.org (check each item's rights), cut five 14-second shots with ffmpeg into C:\Users\you\Videos\dday — the fleet, landing craft, the beach, troops moving inland, crowds — without the original sound. Rights first. “On archive.org” does not mean “public domain”. Use items whose licenseurl is a Public Domain Mark or CC0, or works that are public domain by law (for example films made by the U.S. federal government, such as Army Signal Corps footage). Read the item page’s rights statement, keep the identifiers, and credit the source in the video. When in doubt, skip the item.

Step by step

Each step shows the same calls twice. The kadrctl tab is for PowerShell: a line that starts with kadrctl --% passes JSON, and without --% the same line also works in Command Prompt. The MCP tab is the tool call an agent sends — the tool name and its arguments. Ids such as prj_…, mat_… and seg_… come from the results of earlier steps, so yours will differ. Paths under C:/Users/you are examples.

  1. Find public-domain footage

    The Internet Archive’s advanced search API returns JSON, so an agent with a shell can search directly. Ask for the rights fields and keep only items that are clearly public domain:

    $q = '("d-day" OR normandy) AND year:1944 AND mediatype:movies'
$url = "https://archive.org/advancedsearch.php?q=$([uri]::EscapeDataString($q))" +
       "&fl[]=identifier&fl[]=title&fl[]=year&fl[]=licenseurl&fl[]=rights&rows=50&output=json"
(Invoke-RestMethod $url).response.docs | Format-Table identifier, year, licenseurl, title -AutoSize

    Then list the video files of a chosen item (length is in seconds):

    $item = 'ITEM_ID'   # an identifier from the search
(Invoke-RestMethod "https://archive.org/metadata/$item").files |
  Where-Object { $_.name -like '*.mp4' } | Format-Table name, size, length

    To pick shots, an agent can import a low-resolution copy into a scratch project and use ai.detect_scenes plus preview.contact_sheet to see where each shot starts.

  2. Cut only the shots you need with ffmpeg

    ffmpeg can read straight from the download URL: with -ss before -i it seeks with HTTP range requests, so only a few megabytes per shot are fetched. Re-encoding makes every cut frame-accurate, and -an drops the original commentary. The timecodes below are placeholders — use the ones you picked.

    $src = 'https://archive.org/download/ITEM_ID/FILE.mp4'
$dst = "$env:USERPROFILE\Videos\dday"
New-Item -ItemType Directory -Force $dst | Out-Null
# -ss before -i seeks over HTTP (only the needed bytes are fetched); -t = length; -an drops the old soundtrack
ffmpeg -ss 00:01:12 -i $src -t 14 -c:v libx264 -crf 18 -pix_fmt yuv420p -an "$dst\01_fleet.mp4"
ffmpeg -ss 00:03:40 -i $src -t 14 -c:v libx264 -crf 18 -pix_fmt yuv420p -an "$dst\02_landing_craft.mp4"
ffmpeg -ss 00:05:05 -i $src -t 14 -c:v libx264 -crf 18 -pix_fmt yuv420p -an "$dst\03_beach.mp4"
ffmpeg -ss 00:06:30 -i $src -t 14 -c:v libx264 -crf 18 -pix_fmt yuv420p -an "$dst\04_inland.mp4"
ffmpeg -ss 00:08:15 -i $src -t 14 -c:v libx264 -crf 18 -pix_fmt yuv420p -an "$dst\05_crowds.mp4"

  4. Connect ElevenLabs and pick a voice

  7. Ken Burns moves on every shot

Zooming between 1.36 and 1.48 hides the bars the whole time, and a vertical drift of ±0.06 is safe at that size (the side-to-side slack is tiny). Variations

  • No ElevenLabs key. Use espeak:uk (or any voice from tts.voices) in tts.speak; everything else stays the same. Remove a stored key with tts.set_api_key and clear.
  • Longer films. Narrate paragraph by paragraph (up to 5000 characters per call) and keep one shot per sentence; build the shot list as one dday-shots.json batch.
  • Music bed. Public-domain or CC0 music from the same archive, added with timeline.segment.add at −20 dB (segment.set_volume) under the voice.
  • Projector sound. sfx.add with film_advance at 0 s adds a projector start.
  • Vertical cut. Duplicate the project, switch it to 9:16 and reframe each shot — see One project, three formats.

Tips

  • tts.speak fails with not_found “voice … is not installed” when the ElevenLabs key is missing or the voice id is not in your account’s list — run tts.voices with refresh and copy an id from there.
  • Speech speed for ElevenLabs is limited to 0.7–1.2 (rate); slow narration down there rather than by stretching the clip.
  • Text you synthesise is sent to ElevenLabs; everything else — footage, edits, captions — stays on your PC.
  • Plan shots as data. Keep a small shots.json next to the clips — scene, order, file, duration — and name each file after its source and timecode (for example s2_1_B991.mp4 = scene 2, first shot, source B at 991 s). The plan turns straight into the dday-shots.json batch, and the names make re-cuts and credits easy. A long narration line can be covered by two shots that share its time (say 4.0 s + 3.95 s).
  • Keep the archive identifiers and timecodes in your notes; the end credit should name the source.
