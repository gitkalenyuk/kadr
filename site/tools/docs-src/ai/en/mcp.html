kadr-mcp.exe turns every Kadr command into an MCP tool with the command’s full documentation, and adds one extra tool, kadr_batch. Calls are forwarded to the running engine, so edits show up live in the editor and land in the same undo history.

Setting up a client? See Claude Code, Claude Desktop or other MCP clients. This page explains what the agent gets once connected.

Tool names and arguments

Many clients reject dots in tool names, so dots become underscores. Arguments are exactly the command’s parameters; project commands need project_id.

In these docs the MCP tab of a code block shows the parameters of a tools/call request: {"name": "<tool>", "arguments": {…}}. Each line is one call.

What each tool tells the model

  • Description — what the command does, how it behaves like CapCut, edge cases, then the UI location and hotkey, “Undoable with edit.undo.” for edits, and a Returns: line describing the result.
  • Input schema — JSON Schema with types, enums, ranges, defaults and a description per parameter; units are spelled out (“Unit: microseconds”).
  • Annotations — readOnlyHint on queries such as timeline_get, preview_frame or library_list; destructiveHint on project_delete, so cautious clients confirm it.

Library ids (transitions, effects, filters, animations, fonts, stickers, caption styles, generated presets, sound effects…) are discovered with library_list and library_get rather than guessed.

kadr_batch — several edits, one undo step

kadr_batch runs a list of project commands in order as one atomic step: either every call succeeds and the project is saved once, with a single undo entry “Batch (N actions)”, or nothing changes. Calls use dotted command names, and project_id is filled in for every call. dry_run: true runs the whole list on a copy and returns the results without saving.

[
  {"command": "transition.set", "args": {"segment_id": "seg_8f2a61c04b9e", "type": "whip_pan", "duration_us": 300000}},
  {"command": "segment.set_volume", "args": {"segment_id": "seg_1d93b7e5a0c2", "volume_db": -12}},
  {"command": "text.add", "args": {"text": "Day one", "template_id": "title_bold", "at_us": 0, "duration_us": 2000000}}
]
{"name": "kadr_batch", "arguments": {"project_id": "prj_5c1e7a9d3b20", "calls": [
  {"command": "transition.set", "args": {"segment_id": "seg_8f2a61c04b9e", "type": "whip_pan", "duration_us": 300000}},
  {"command": "segment.set_volume", "args": {"segment_id": "seg_1d93b7e5a0c2", "volume_db": -12}},
  {"command": "text.add", "args": {"text": "Day one", "template_id": "title_bold", "at_us": 0, "duration_us": 2000000}}
]}}
kadrctl batch prj_5c1e7a9d3b20 demo-batch.json
curl -s http://127.0.0.1:7777/api/v1/projects/prj_5c1e7a9d3b20/batch -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"dry_run":false,"calls":[{"command":"transition.set","args":{"segment_id":"seg_8f2a61c04b9e","type":"whip_pan","duration_us":300000}},{"command":"segment.set_volume","args":{"segment_id":"seg_1d93b7e5a0c2","volume_db":-12}},{"command":"text.add","args":{"text":"Day one","template_id":"title_bold","at_us":0,"duration_us":2000000}}]}'

The result holds one entry per call, in order: {"results": [ … ], "dry_run": false}.

  • No references between calls. Arguments are fixed before the batch runs, so a call cannot use an id created by an earlier call in the same batch. Create things first, read their ids, then batch the follow-up edits.
  • Project commands only. Global commands (for example export.start, project.create, library.list) and edit.undo/edit.redo are rejected: call 0: export.start is not a project command and cannot be batched (call numbers start at 0).
  • Runtime errors return the failing command’s own error (with its hint); the working copy is discarded.
  • Side effects outside the project (generated media files, speech files in the cache) are not rolled back by a failed batch or a dry run — they are only files.

Pictures the model can see

Results that contain a png_base64 field are returned as an MCP image block plus a text block with the remaining fields. That applies to preview_frame (one composited frame, exactly as exported), preview_contact_sheet (a grid of frames across the edit, with times_us for each tile) and library_preview (how a transition, effect, filter, animation, text look, caption style, animated sticker or generated clip plays — look before you choose; see Library, previews and fonts). For measurements use preview_layout: it returns the box of every visible clip, text and sticker in canvas pixels. See Verifying results.

Errors

A failed call is a tool result with "isError": true whose text is the engine’s error as JSON:

{"name": "segment_set_volume", "arguments": {"project_id": "prj_5c1e7a9d3b20", "segment_id": "seg_nope", "volume_db": -6}}
Error: {
  "code": "not_found",
  "message": "segment \"seg_nope\" not found",
  "hint": "Call project.get (tracks[].segments[].id) or timeline.get to list valid segment ids.",
  "field": "segment_id"
}

Read the hint: it says how to fix the call. Codes are listed in REST API → Errors; not_available means an optional local component (Whisper, a matting model, a speech engine, FFmpeg) is missing on this PC.

Long-running tools

  • The bridge waits up to 5 minutes for a call. Captions, transcription, background removal and exports run as background jobs: call them without wait and poll captions_status (supports wait_s long polling), ai_jobs or export_status.
  • export_start always returns immediately with a job_id; exports run one at a time and extra jobs wait in state queued.

Engine discovery and auto-start

The bridge connects to KADR_ADDR (default 127.0.0.1:7777) with the token from KADR_TOKEN or the data folder. If nothing answers, it starts kadr-server.exe from its own folder and waits up to 10 seconds. That headless engine keeps running after the client exits, so later sessions start instantly; quit it in Task Manager before opening the editor if you want to watch edits live.

The tool list comes from the running engine, so it always matches the installed version. On initialize the server also sends short instructions: projects contain tracks, tracks contain segments, times are microseconds, read state first, use kadr_batch for multi-step edits, look at preview_frame after visual edits, and follow error hints.
