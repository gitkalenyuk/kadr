kadr-mcp.exe перетворює кожну команду Kadr на інструмент MCP з повною документацією команди й додає ще один інструмент — kadr_batch. Виклики пересилаються в запущений рушій, тож правки з’являються наживо в редакторі й потрапляють у ту саму історію скасування.

Налаштовуєте клієнт? Див. Claude Code, Claude Desktop або інші MCP-клієнти. Ця сторінка пояснює, що отримує агент після під’єднання.

Назви інструментів і аргументи

Багато клієнтів не приймають крапок у назвах інструментів, тож крапки стають підкресленнями. Аргументи — рівно параметри команди; проєктні команди потребують project_id.

project.createproject_create{"name": "Trip", "ratio": "9:16"}
timeline.segment.splittimeline_segment_split{"project_id": "prj_…", "segment_id": "seg_…", "at_us": 2500000}
captions.autocaptions_auto{"project_id": "prj_…", "language": "uk", "wait": true}
preview.framepreview_frame{"project_id": "prj_…", "time_us": 1000000, "width": 960}
edit.undoedit_undo{"project_id": "prj_…"}

У цій документації вкладка MCP блоку коду показує параметри запиту tools/call: {"name": "<tool>", "arguments": {…}}. Кожен рядок — один виклик.

Що кожен інструмент повідомляє моделі

  • Опис — що робить команда, як вона поводиться порівняно з CapCut, граничні випадки, далі місце в інтерфейсі та гаряча клавіша, «Undoable with edit.undo.» для правок і рядок Returns: з описом результату.
  • Схема входу — JSON Schema з типами, переліками, діапазонами, типовими значеннями й описом кожного параметра; одиниці прописано явно («Unit: microseconds»).
  • Анотації — readOnlyHint на запитах на кшталт timeline_get, preview_frame чи library_list; destructiveHint на project_delete, тож обережні клієнти перепитують.

Ідентифікатори бібліотеки (переходи, ефекти, фільтри, анімації, шрифти, стікери, стилі субтитрів, пресети генерації, звукові ефекти…) слід знаходити через library_list і library_get, а не вгадувати.

kadr_batch — кілька правок, один крок скасування

kadr_batch виконує список проєктних команд по черзі як один атомарний крок: або всі виклики вдаються і проєкт зберігається один раз з одним записом скасування «Batch (N actions)», або нічого не змінюється. Виклики використовують назви команд із крапками, а project_id підставляється в кожен виклик. dry_run: true проганяє весь список на копії й повертає результати без збереження.

  {"command": "text.add", "args": {"text": "Day one", "template_id": "title_bold", "at_us": 0, "duration_us": 2000000}}
]

  {"command": "segment.set_volume", "args": {"segment_id": "seg_1d93b7e5a0c2", "volume_db": -12}},

Результат містить по одному запису на виклик у тому самому порядку: {"results": [ … ], "dry_run": false}.

  • Без посилань між викликами. Аргументи фіксуються до запуску пакета, тож виклик не може використати ідентифікатор, створений попереднім викликом того самого пакета. Спершу створіть об’єкти, прочитайте їхні id, а потім пакетом робіть наступні правки.
  • Лише проєктні команди. Глобальні команди (наприклад, export.start, project.create, library.list) та edit.undo/edit.redo відхиляються: call 0: export.start is not a project command and cannot be batched (нумерація викликів з 0).
  • Помилки під час виконання повертають власну помилку команди, що впала (з її підказкою); робоча копія відкидається.
  • Побічні ефекти поза проєктом (згенеровані медіафайли, файли мовлення в кеші) не відкочуються ні невдалим пакетом, ні пробним запуском — це просто файли.

Зображення, які бачить модель

Результати з полем png_base64 повертаються як блок MCP image плюс текстовий блок з рештою полів. Так працюють preview_frame (один скомпонований кадр — рівно як в експорті) і preview_contact_sheet (сітка кадрів по всьому монтажу з times_us для кожної плитки). Для вимірювань використовуйте preview_layout: він повертає рамку кожного видимого кліпу, тексту й стікера в пікселях полотна. Див. Перевірка результату.

Помилки

Невдалий виклик — це результат інструмента з "isError": true, текст якого — помилка рушія у форматі JSON:

{"name": "segment_set_volume", "arguments": {"project_id": "prj_5c1e7a9d3b20", "segment_id": "seg_nope", "volume_db": -6}}
Error: {
  "code": "not_found",
  "message": "segment \"seg_nope\" not found",
  "hint": "Call project.get (tracks[].segments[].id) or timeline.get to list valid segment ids.",
  "field": "segment_id"
}

Читайте hint: він пояснює, як виправити виклик. Коди перелічено в REST API → Помилки; not_available означає, що на цьому ПК бракує необов’язкового локального компонента (Whisper, моделі матування, рушія мовлення, FFmpeg).

Довгі завдання

  • Міст чекає на виклик до 5 хвилин. Субтитри, транскрипція, видалення фону й експорт — фонові завдання: викликайте їх без wait і опитуйте captions_status (підтримує довге опитування через wait_s), ai_jobs або export_status.
  • export_start завжди повертається одразу з job_id; експорти виконуються по одному, а зайві завдання чекають у стані queued.

Пошук рушія і автозапуск

Міст під’єднується до KADR_ADDR (типово 127.0.0.1:7777) з токеном із KADR_TOKEN або з папки даних. Якщо ніхто не відповідає, він запускає kadr-server.exe зі своєї папки й чекає до 10 секунд. Цей «безголовий» рушій працює й після виходу клієнта, тож наступні сесії стартують миттєво; завершіть його в Диспетчері завдань перед відкриттям редактора, якщо хочете бачити правки наживо.

Список інструментів береться із запущеного рушія, тож завжди відповідає встановленій версії. На initialize сервер також надсилає короткі інструкції: проєкти містять доріжки, доріжки — сегменти, час у мікросекундах, спершу читати стан, для багатокрокових правок — kadr_batch, після візуальних правок дивитися preview_frame, дотримуватися підказок у помилках.
