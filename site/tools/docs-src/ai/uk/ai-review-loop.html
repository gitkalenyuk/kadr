Результат — монтаж, перевірений «на око», а не просто зібраний. Claude рендерить відео, дивиться на кадри, вимірює те, що виглядає не так, виправляє, рендерить знову для підтвердження і скасовує будь-яку зміну, що погіршила результат. Використовуйте після будь-якого іншого рецепта або для проєкту, змонтованого вручну.

  • Час: ~1 хв
  • Що потрібно: Будь-який проєкт Kadr
  • Основні команди: preview.contact_sheet, preview.layout, preview.frame, keyframe.list, keyframe.add, segment.set_transform, edit.undo, edit.history

Попросіть Claude

Перевір мій проєкт Kadr «Summer recap» перед експортом. Відрендер контактний аркуш усього відео й пошукай чорні краї чи смуги, текст, обрізаний рамкою кадру, текст, що перекриває інший текст чи стікери, і чорні кадри між кліпами. Усе підозріле виміряй через preview_layout і подивися саме цей кадр через preview_frame. Виправ знайдене, після кожного виправлення відрендер кадр ще раз для підтвердження і скасуй усе, що не стало кращим. Потім дай короткий список змін.

Крок за кроком

Кожен крок показує ті самі виклики двічі. Вкладка kadrctl — для PowerShell: рядок, що починається з kadrctl --%, передає JSON, а без --% той самий рядок працює і в командному рядку (cmd). Вкладка MCP — це виклик інструмента, який надсилає агент: назва інструмента та його аргументи. Ідентифікатори на кшталт prj_…, mat_… і seg_… беруться з результатів попередніх кроків, тож у вас вони будуть інші. Шляхи в C:/Users/you — лише приклад.

  1. Охопіть увесь монтаж одним поглядом

    Через MCP preview_contact_sheet і preview_frame повертаються як зображення, тож Claude справді бачить результат. Через kadrctl чи REST ви отримуєте той самий PNG у base64 в полі png_base64 або JPEG з ендпоінта кадру.

    preview.contact_sheet рендерить рівномірно розподілені кадри в одну сітку рендерером експорту. times_us у результаті — час кожної плитки, тож будь-яку знахідку легко знайти знову.

    kadrctl run project.list --query "Summer recap"
kadrctl run preview.contact_sheet --project_id prj_b8d196d1dd0b --count 8 --columns 4 --tile_width 240
    {"name": "project_list", "arguments": {"query": "Summer recap"}}
{"name": "preview_contact_sheet", "arguments": {"project_id": "prj_b8d196d1dd0b", "count": 8, "columns": 4, "tile_width": 240}}

    У цьому проєкті плитки з першого кліпу показують тонку чорну смугу вздовж правого краю, а титр «Summer 2026» обрізаний унизу кадру.

  2. Виміряйте проблему

    preview.layout дає точну рамку кожного видимого кліпу й тексту в заданий момент, у пікселях полотна (тут 1920×1080):

    kadrctl run preview.layout --project_id prj_b8d196d1dd0b --time_us 0.3s
    {"name": "preview_layout", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000}}
    photo  seg_f04569603fd9  x -58    y 0      right 1863  bottom 1080
text   seg_7f6cd623c899  x 693    y 1010   right 1228  bottom 1096

    Фото закінчується на x = 1863, тож праворуч лишається 57 px чорного. Титр закінчується на y = 1096 — на 16 px нижче низу кадру.

  3. Знайдіть причину

    keyframe.list показує рух Кена Бернса на фото: він починається з масштабу 1.0 при зсуві x = −0.06. При масштабі 1 фото рівно заповнює кадр, тож будь-який зсув убік відкриває край — фото можна зсунути щонайбільше на масштаб − 1.

    kadrctl run keyframe.list --project_id prj_b8d196d1dd0b --segment_id seg_f04569603fd9 --property transform
    {"name": "keyframe_list", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_f04569603fd9", "property": "transform"}}

  4. Виправте обидві проблеми

    keyframe.add у момент наявного ключового кадру оновлює його, тож рух тепер починається зі 112%. segment.set_transform піднімає титр до y = 0.6 (+1 поставило б його центр на нижній край; +Y — донизу).

    kadrctl run keyframe.add --project_id prj_b8d196d1dd0b --segment_id seg_f04569603fd9 --property transform.scale --time_us 0 --value 1.12
kadrctl run segment.set_transform --project_id prj_b8d196d1dd0b --segment_id seg_7f6cd623c899 --y 0.6
    {"name": "keyframe_add", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_f04569603fd9", "property": "transform.scale", "time_us": 0, "value": 1.12}}
{"name": "segment_set_transform", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_7f6cd623c899", "y": 0.6}}

  5. Підтвердьте виправлення

    Той самий момент — виміряно й відрендерено знову:

    kadrctl run preview.layout --project_id prj_b8d196d1dd0b --time_us 0.3s
kadrctl run preview.frame --project_id prj_b8d196d1dd0b --time_us 0.3s --width 960
    {"name": "preview_layout", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000}}
{"name": "preview_frame", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000, "width": 960}}
    photo  x -173   right 1978   bottom 1145     covers the frame
text   x 693    right 1228   bottom 907      inside the frame

  6. Спробуйте ідею й лишіть її, лише якщо вона допомагає

    Правки в редакторі й правки Claude мають одну спільну історію скасування. Claude пробує сміливіший титр через text.apply_effect (fx_comic), дивиться на кадр, вирішує, що він конфліктує з фото, і повертає все через edit.undo. edit.history підтверджує, що саме можна повторити.

kadrctl run edit.undo --project_id prj_b8d196d1dd0b

    Останній контактний аркуш підтверджує, що більше нічого не змінилося; export.estimate показує розмір і тривалість результату ще до справжнього експорту.

Поради

  • Контактні аркуші дешеві: 8–12 плиток по 240–320 px досить, щоб оцінити композицію й темп. start_us і end_us наближають один фрагмент.
  • preview.frame з width 960 і більше — правильний інструмент, щоб прочитати дрібний текст.
  • Попросіть наприкінці короткий список змін. Кожне виправлення є в історії скасування, тож у редакторі можна пройтися по них назад.
