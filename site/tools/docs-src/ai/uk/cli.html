kadrctl запускає будь-яку команду Kadr із термінала. Він бере параметри кожної команди із запущеного рушія, перетворює значення на потрібні типи (зокрема час на кшталт 2.5s) і друкує результат як JSON — зручно для швидких правок, скриптів і агентів, які мають лише оболонку.

Налаштування

kadrctl.exe встановлюється поруч із Kadr.exe у %LOCALAPPDATA%\Programs\Kadr\. З опцією інсталятора Додати kadrctl і kadr-mcp до PATH (типово ввімкнена) він працює з будь-якого нового термінала: kadrctl help, kadrctl version.

На відміну від kadr-mcp, kadrctl не запускає рушій: Kadr або kadr-server.exe мають працювати. Адресу й токен він сам знаходить у %APPDATA%\Kadr.

Як записувати параметри

Кожен параметр стає прапорцем з тією самою назвою; kadrctl перетворює значення на тип параметра. Невідомі прапорці відхиляються ще до виконання.

Логічне--wait, --wait true, --snap falseГолий прапорець означає true.

Лапки для JSON у Windows

Параметри-масиви й об’єкти (paths, segment_ids, style, params, points…) — це JSON, і його подвійні лапки мають пережити оболонку:

ОболонкаПишіть
Командний рядок (cmd)--paths "[\"C:/Users/you/Videos/trip\"]"
PowerShell 7.3+--paths '["C:/Users/you/Videos/trip"]'
Windows PowerShell 5.1--paths '[\"C:/Users/you/Videos/trip\"]'
Будь-який PowerShellkadrctl --% run media.import --project_id prj_… --paths "[\"C:/Users/you/Videos/trip\"]"

Документація використовує форму з --%: вона працює в будь-якій версії PowerShell, а без --% той самий рядок працює в cmd. Після --% PowerShell перестає розбирати рядок, тож $змінні не підставляються. У JSON пишіть шляхи з прямими косими рисками (C:/Users/you) або подвоєними зворотними. У PowerShell беріть у лапки кольори ("#FFD400" — # починає коментар), а текст із $ — в одинарні лапки.

Пакетні файли

Пакетний файл — це JSON-масив об’єктів {command, args} без project_id (він береться з командного рядка). --dry-run перевіряє пакет на копії без збереження. Зберігайте файл у UTF-8 без BOM: kadrctl відхиляє BOM, а Set-Content -Encoding UTF8 у Windows PowerShell 5.1 його додає — користуйтеся [IO.File]::WriteAllText(), як у скрипті нижче.

[
  { "command": "transition.apply_all", "args": { "type": "mix", "duration_us": 400000 } },
  { "command": "text.add", "args": { "text": "Тур кухнею", "template_id": "title_bold", "at_us": 0, "duration_us": 2500000 } }
]
kadrctl batch prj_9d2e4c7a1b05 calls.json --dry-run
kadrctl batch prj_9d2e4c7a1b05 calls.json

Скрипти в PowerShell

Цей скрипт робить вертикальний перекадрований шортс із кожного .mp4 у папці й ставить експорти в чергу. Працює у Windows PowerShell 5.1 і PowerShell 7. Допоміжна функція kadr перетворює JSON від kadrctl на об’єкти й зупиняється на помилках; kadr-batch передає JSON через файл, тож шляхи з пробілами не потребують лапок.

$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [Text.Encoding]::UTF8   # read non-English names correctly

# Run kadrctl and turn its JSON output into PowerShell objects.
function kadr {
  $out = kadrctl @args
  if ($LASTEXITCODE -ne 0) { throw "kadrctl $($args[0]) $($args[1]) failed" }
  $out | Out-String | ConvertFrom-Json
}

# Run calls as one batch. JSON goes through a file, so no shell quoting is involved.
function kadr-batch($ProjectId, $Calls) {
  $file = Join-Path $env:TEMP 'kadr-calls.json'
  [IO.File]::WriteAllText($file, (ConvertTo-Json -InputObject @($Calls) -Depth 10))  # UTF-8, no BOM
  kadr batch $ProjectId $file
}

$src = "$env:USERPROFILE\Videos\Raw"
$dst = "$env:USERPROFILE\Videos\Kadr\Shorts"

Get-ChildItem $src -Filter *.mp4 | ForEach-Object {
  $p   = kadr run project.create --name $_.BaseName --ratio 9:16
  $imp = kadr-batch $p.id @(@{ command = 'media.import'; args = @{ paths = @($_.FullName) } })
  $seg = kadr run timeline.segment.add --project_id $p.id --material_id $imp.results[0].materials[0].id
  kadr run ai.auto_reframe --project_id $p.id --segment_id $seg.segment.id --ratio 9:16 | Out-Null
  $job = kadr run export.start --project_id $p.id --resolution 1080p --path "$dst\$($_.BaseName).mp4"
  "{0} -> {1} ({2})" -f $_.Name, $job.path, $job.state
}

kadr run export.list | Format-Table job_id, state, progress, path
  • Експорти виконуються по одному; зайві завдання чекають як queued, тож цикл завершується задовго до відео.
  • export.estimate показує підсумковий розмір і шлях без експорту.
  • Щоб безпечно перевірити скрипт, спрямуйте його на окремий рушій: $env:KADR_DATA_DIR і $env:KADR_ADDR і для kadr-server.exe, і для kadrctl.

Коди виходу й помилки

У разі успіху kadrctl друкує результат у стандартний вивід і завершується з кодом 0. У разі помилки друкує її у стандартний потік помилок і завершується з кодом 1:

error [not_found]: project "prj_nope" not found
hint: Call project.list to get valid project ids.

Проблеми, знайдені ще до надсилання виклику, починаються з простого error::

error: project.list has no parameter "foo" (see `kadrctl describe project.list`)
error: cannot reach Kadr at http://127.0.0.1:7777 (is the editor or `kadr-server` running?): …

Коди помилок — ті самі, що в REST API.
