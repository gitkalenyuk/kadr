Команди Kadr поблажливі — будь-яку правку можна скасувати, — але агент, що працює в правильному порядку, отримує кращі відео меншою кількістю викликів. Ось звички, які важать найбільше, і пастки, в які агенти потрапляють найчастіше.

Спершу читайте, потім пишіть

  • Починайте кожну сесію з project.list або project.get/timeline.get. Беріть id з результатів — ніколи не складайте й не вгадуйте їх.
  • Шукайте id бібліотеки через library.list (kind: transition, effect, filter, animation, text_template, text_effect, text_animation, caption_style, sticker, font, generated, sound_effect, voice_effect), а незнайомі параметри перевіряйте через kadrctl describe чи довідник.
  • Перечитуйте стан після правок, що створюють чи прибирають кліпи: розрізи, ai.remove_silence, ai.split_scenes, вирізання за транскриптом і зсуви магніту змінюють id і час. Результати зазвичай містять нові id (segment_ids, left/right); якщо ні — викличте timeline.get знову.

Плануйте, потім пакетуйте

  • Об’єднуйте пов’язані правки в один kadr_batch (MCP), POST /projects/{id}/batch (REST) чи kadrctl batch: вони застосовуються атомарно, одним кроком скасування, а людина бачить одну чисту зміну.
  • Перевіряйте великий план через dry_run — він проганяє кожен виклик на копії й повідомляє першу помилку, нічого не зберігаючи.
  • Працюйте етапами: створіть об’єкти (і прочитайте їхні id) → пакетом зробіть наступні правки. Пакет не може посилатися на id, створені всередині нього ж.
  • Глобальні команди (експорт, завдання субтитрів, створення/дублювання/видалення проєктів, бібліотека, пресети) пакетувати не можна.

Слухайтеся підказок у помилках

Помилки містять code, message, hint і часто field. Підказку написано для агентів — вона називає команду, що показує допустимі значення, або пояснює порушене правило:

{"name": "transition_set", "arguments": {"project_id": "prj_c0d7a4e19b5f", "segment_id": "seg_f8a1d3c6e204", "type": "mix"}}
kadrctl run transition.set --project_id prj_c0d7a4e19b5f --segment_id seg_f8a1d3c6e204 --type mix
error [conflict]: segment seg_f8a1d3c6e204 is the last clip on its track; a transition needs a following clip
hint: Transitions sit between two touching clips on the same track: pass the LEFT clip of the pair (the one that ends where the next one starts).

Довгі завдання: чекати чи опитувати

  • Фонові завдання: captions.auto, transcript.transcribe, ai.remove_background, export.start. Вони одразу повертають job_id.
  • wait: true (субтитри, транскрипція, видалення фону) блокує виклик до завершення — нормально для кількох хвилин медіа, але MCP і kadrctl здаються через 5 хвилин.
  • Для довшого медіа запускайте без wait і робіть довге опитування captions.status з wait_s (до 600 с за виклик); export.status опитуйте кожні 1–2 с; або слухайте події captions.done/export.done.
  • Перший запуск Whisper завантажує модель і триває довше. Експорти виконуються по одному; зайві завдання — queued. Після перезапуску Kadr завдання забуваються.

Пастки таймлайну

  • Не боріться з магнітом. На основній доріжці at_us притягується до найближчої межі кліпів, і все зсувається. Будуйте послідовності по порядку, для вільного розміщення беріть доріжки накладання або вимкніть магніт через timeline.settings.set.
  • Точні позиції потребують snap: false у timeline.segment.move і timeline.segment.trim — інакше край у межах 100 мс від маркера, курсора чи іншого краю стрибне до нього.
  • Властивості з ключовими кадрами: щойно властивість має ключові кадри, segment.set_* записує ключовий кадр у позиції курсора. Змінюйте анімовані значення через keyframe.add з явним часом.
  • Переходи ставляться на лівий кліп і потребують кліпів, що торкаються; тривалість обмежена половиною коротшого кліпу.
  • Фільтри й ефекти на доріжках діють на все під ними — зокрема на текст, якщо текстова доріжка нижче. Додавайте їх до титрів або застосовуйте до кліпів.
  • Одиниці: час у мкс; volume_db у дБ, але ключові кадри volume лінійні; позиції в частках полотна, +Y донизу; scale 1 — вписати, а не заповнити.

Файли й шляхи

  • Шляхи абсолютні й стосуються ПК, на якому працює Kadr. У JSON пишіть прямі косі риски (C:/Users/you/Videos) або подвоєні зворотні.
  • Папка в media.import імпортує медіафайли, що лежать безпосередньо в ній (без підпапок, до 500); файли, що вже є в проєкті, повертаються як duplicates.
  • Експорт ніколи не перезаписує файли без overwrite — читайте кінцевий path з результату. Без path файли йдуть у %USERPROFILE%\Videos\Kadr\<назва проєкту>.mp4.

Тримайте результати компактними

  • timeline.get замість project.get для орієнтації; segment.get — для детального огляду одного кліпу.
  • include_words: false у captions.list; include_words: false у transcript.get, коли потрібен лише текст.
  • Контактні аркуші на 8–12 плиток по 240–320 px; окремі кадри на 960 px — лише щоб прочитати дрібний текст.

Поважайте людину

  • Відкрийте проєкт у вікні (ui.open_project) і коментуйте етапи через ui.toast — див. Робота на очах у людини.
  • Робіть варіанти через project.duplicate, а не перезаписуйте готовий монтаж; ніколи не викликайте project.delete без запиту.
  • Не вставляйте токен API чи ключі хмарних сервісів у запити, файли чи журнали; tts.set_api_key зберігає ключі локально й ніколи їх не повертає.
  • Завершуйте коротким звітом: що змінено, де експорт, що не вдалося перевірити.
