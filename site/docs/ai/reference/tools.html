Tools commands

4 commands in the Tools category. Each one works the same from the editor UI, REST, MCP and kadrctl.

  • tools.cancelCancel FFmpeg download
  • tools.install_ffmpegDownload FFmpeg
  • tools.set_ffmpeg_dirUse my FFmpeg
  • tools.statusTools status

tools.cancel

Cancel FFmpeg download

No undo stepFirst run › CancelMCP tools_cancel

Stops a running tools.install_ffmpeg download (the Cancel button under the progress bar). The partial file is deleted and the job ends in state "cancelled"; FFmpeg stays missing until tools.install_ffmpeg is called again. Does nothing (cancelled=false) when no download is running.

Parameters

No parameters.

Returns

{cancelled: true when a running download was stopped}.

Examples

Cancel the download

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.cancel \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run tools.cancel
// MCP tool: tools_cancel
{}

tools.install_ffmpeg

Download FFmpeg

No undo stepFirst run › Download FFmpegMCP tools_install_ffmpeg

Downloads FFmpeg for Kadr — the first-run "Download now" button. Fetches the BtbN GPL build of FFmpeg 7.1 for Windows x64 (about 100 MB) from GitHub, verifies its SHA-256 against the checksums.sha256 file of the same release (a mismatch deletes the download and fails), then extracts ONLY ffmpeg.exe and ffprobe.exe into %LOCALAPPDATA%\Kadr\tools\ffmpeg\bin where Kadr finds them immediately (no restart). Runs in the background and returns at once unless wait=true; progress arrives as tools.progress events (state downloading → verifying → extracting → done | failed | cancelled), or poll tools.status; stop it with tools.cancel. When FFmpeg is already available (PATH, next to Kadr, chosen folder) nothing is downloaded and already_installed=true, unless force=true. FFmpeg is licensed under the GPL (https://ffmpeg.org/legal.html). Only supported on Windows x64 (not_available elsewhere).

Parameters

ParameterTypeDescription
forcebooleanDownload Kadr's own copy even when an FFmpeg is already found (e.g. a broken or very old one on PATH).
Default false
sourcestringDownload source. Only "btbn" (github.com/BtbN/FFmpeg-Builds, GPL build, FFmpeg 7.1 branch) is available.
One of btbnDefault "btbn"
waitbooleanBlock until the download is verified and installed (can take minutes) instead of returning immediately.
Default false

Returns

{started, already_installed, message, ...tools.status fields}.

Examples

Download FFmpeg in the background

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.install_ffmpeg \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run tools.install_ffmpeg
// MCP tool: tools_install_ffmpeg
{}

Download and wait until installed

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.install_ffmpeg \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"wait":true}'
kadrctl run tools.install_ffmpeg --wait
// MCP tool: tools_install_ffmpeg
{
  "wait": true
}

tools.set_ffmpeg_dir

Use my FFmpeg

No undo stepFirst run › I have FFmpegMCP tools_set_ffmpeg_dir

Points Kadr at an FFmpeg that is already on this computer — "I have FFmpeg — choose folder". The folder (or its bin subfolder) must contain both ffmpeg.exe and ffprobe.exe and ffmpeg must run ("-version"); it is saved as ffmpeg_dir in settings.json, used from now on (no restart) and on every start, and takes precedence over the copy next to Kadr, the downloaded copy and PATH. clear=true forgets the folder.

Parameters

ParameterTypeDescription
clearbooleanForget the chosen folder and go back to automatic lookup.
Default false
dirstringAbsolute folder path, e.g. "C:\\ffmpeg\\bin" or "C:\\ffmpeg" (its bin subfolder is checked too). Required unless clear is true.

Returns

The tools.status object after the change.

Examples

Use FFmpeg from C:\ffmpeg\bin

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.set_ffmpeg_dir \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"dir":"C:\\ffmpeg\\bin"}'
kadrctl run tools.set_ffmpeg_dir --dir 'C:\ffmpeg\bin'
// MCP tool: tools_set_ffmpeg_dir
{
  "dir": "C:\\ffmpeg\\bin"
}

Forget the folder

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.set_ffmpeg_dir \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{"clear":true}'
kadrctl run tools.set_ffmpeg_dir --clear
// MCP tool: tools_set_ffmpeg_dir
{
  "clear": true
}

tools.status

Tools status

No undo stepSettings › FFmpegMCP tools_status

Reports whether FFmpeg and FFprobe — required for importing, previewing and exporting media — are available, where they were found (source: env = KADR_FFMPEG, custom_dir = folder chosen with tools.set_ffmpeg_dir, next_to_exe, downloaded = Kadr's tools folder, path = system PATH) and their version, plus the state of a running tools.install_ffmpeg download and where it would download from (source, license, approximate size). Kadr does not bundle FFmpeg; when ffmpeg.found is false call tools.install_ffmpeg (Windows x64) or tools.set_ffmpeg_dir.

Parameters

No parameters.

Returns

{ffmpeg{found, ffmpeg_path, ffprobe_path, version, source, error}, tools_dir, ffmpeg_dir, auto_download_supported, install{tool, state idle|downloading|verifying|extracting|done|failed|cancelled, downloaded_bytes, total_bytes, progress, error}, source{id, name, url, checksums_url, page, license, license_url, approx_size_mb}}.

Examples

Is FFmpeg installed?

curl -X POST http://127.0.0.1:7777/api/v1/commands/tools.status \
  -H "Authorization: Bearer $KADR_TOKEN" \
  -d '{}'
kadrctl run tools.status
// MCP tool: tools_status
{}
