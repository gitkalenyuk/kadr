For AI agentsRecipes4 min read

Let Claude review and fix its own edit

You get an edit that has been checked by eye, not just assembled. Claude renders the video, looks at the frames, measures what looks wrong, fixes it, renders again to confirm, and undoes any change that made things worse. Use it after any other recipe, or on a project you edited by hand.

  • Time: ~1 min
  • You need: Any Kadr project
  • Main commands: preview.contact_sheet, preview.layout, preview.frame, keyframe.list, keyframe.add, segment.set_transform, edit.undo, edit.history

Ask Claude

Review my Kadr project "Summer recap" before I export it. Render a contact sheet of the whole video and look for black edges or bars, text cut off by the frame, text overlapping other text or stickers, and black frames between clips. For anything suspicious, measure it with preview_layout and look at that exact frame with preview_frame. Fix what you find, render the frame again to confirm each fix, and undo any change that doesn't look better. Then give me a short list of what you changed.

Step by step

Each step shows the same calls twice. The kadrctl tab is for PowerShell: a line that starts with kadrctl --% passes JSON, and without --% the same line also works in Command Prompt. The MCP tab is the tool call an agent sends — the tool name and its arguments. Ids such as prj_…, mat_… and seg_… come from the results of earlier steps, so yours will differ. Paths under C:/Users/you are examples.

  1. Look at the whole edit at once

    Through MCP, preview_contact_sheet and preview_frame come back as images, so Claude actually sees the result. With kadrctl or REST you get the same PNG as base64 in png_base64, or a JPEG from the frame endpoint.

    preview.contact_sheet renders evenly spaced frames into one grid with the export renderer. times_us in the result gives the time of each tile, so anything spotted can be found again.

    kadrctl run project.list --query "Summer recap"
kadrctl run preview.contact_sheet --project_id prj_b8d196d1dd0b --count 8 --columns 4 --tile_width 240
    {"name": "project_list", "arguments": {"query": "Summer recap"}}
{"name": "preview_contact_sheet", "arguments": {"project_id": "prj_b8d196d1dd0b", "count": 8, "columns": 4, "tile_width": 240}}

    In this project the tiles from the first clip show a thin black strip along the right edge, and the title “Summer 2026” is cut off at the bottom of the frame.

  2. Measure the problem

    preview.layout gives the exact box of every visible clip and text at a given time, in canvas pixels (1920×1080 here):

    kadrctl run preview.layout --project_id prj_b8d196d1dd0b --time_us 0.3s
    {"name": "preview_layout", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000}}
    photo  seg_f04569603fd9  x -58    y 0      right 1863  bottom 1080
text   seg_7f6cd623c899  x 693    y 1010   right 1228  bottom 1096

    The photo ends at x = 1863, which leaves 57 px of black on the right. The title ends at y = 1096, 16 px below the bottom of the frame.

  3. Find the cause

    keyframe.list shows the photo’s Ken Burns move: it starts at scale 1.0 while shifted to x = −0.06. At scale 1 the photo exactly fills the frame, so any sideways shift shows an edge — a photo can shift by at most scale − 1.

    kadrctl run keyframe.list --project_id prj_b8d196d1dd0b --segment_id seg_f04569603fd9 --property transform
    {"name": "keyframe_list", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_f04569603fd9", "property": "transform"}}

  4. Fix both problems

    keyframe.add at an existing keyframe’s time updates that keyframe, so the move now starts at 112%. segment.set_transform moves the title up to y = 0.6 (+1 would put its centre on the bottom edge; +Y is down).

    kadrctl run keyframe.add --project_id prj_b8d196d1dd0b --segment_id seg_f04569603fd9 --property transform.scale --time_us 0 --value 1.12
kadrctl run segment.set_transform --project_id prj_b8d196d1dd0b --segment_id seg_7f6cd623c899 --y 0.6
    {"name": "keyframe_add", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_f04569603fd9", "property": "transform.scale", "time_us": 0, "value": 1.12}}
{"name": "segment_set_transform", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_7f6cd623c899", "y": 0.6}}

  5. Confirm the fix

    Same time, measured and rendered again:

    kadrctl run preview.layout --project_id prj_b8d196d1dd0b --time_us 0.3s
kadrctl run preview.frame --project_id prj_b8d196d1dd0b --time_us 0.3s --width 960
    {"name": "preview_layout", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000}}
{"name": "preview_frame", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000, "width": 960}}
    photo  x -173   right 1978   bottom 1145     covers the frame
text   x 693    right 1228   bottom 907      inside the frame

  6. Try an idea, keep it only if it helps

    Edits made in the editor and by Claude share one undo history. Claude tries a bolder title with text.apply_effect (fx_comic), looks at the frame, decides it clashes with the photo, and takes it back with edit.undo. edit.history confirms what would be redone.

    kadrctl run text.apply_effect --project_id prj_b8d196d1dd0b --segment_id seg_7f6cd623c899 --effect_id fx_comic
kadrctl run preview.frame --project_id prj_b8d196d1dd0b --time_us 0.3s --width 960
kadrctl run edit.undo --project_id prj_b8d196d1dd0b
kadrctl run edit.history --project_id prj_b8d196d1dd0b
    {"name": "text_apply_effect", "arguments": {"project_id": "prj_b8d196d1dd0b", "segment_id": "seg_7f6cd623c899", "effect_id": "fx_comic"}}
{"name": "preview_frame", "arguments": {"project_id": "prj_b8d196d1dd0b", "time_us": 300000, "width": 960}}
{"name": "edit_undo", "arguments": {"project_id": "prj_b8d196d1dd0b"}}
{"name": "edit_history", "arguments": {"project_id": "prj_b8d196d1dd0b"}}
    { "can_undo": true, "can_redo": true, "undo_label": "Set transform", "redo_label": "Apply text effect" }

  7. Final pass

    A last contact sheet confirms nothing else changed; export.estimate reports the output size and length before the real export.

    kadrctl run preview.contact_sheet --project_id prj_b8d196d1dd0b --count 8 --columns 4 --tile_width 240
kadrctl run export.estimate --project_id prj_b8d196d1dd0b --resolution 1080p
    {"name": "preview_contact_sheet", "arguments": {"project_id": "prj_b8d196d1dd0b", "count": 8, "columns": 4, "tile_width": 240}}
{"name": "export_estimate", "arguments": {"project_id": "prj_b8d196d1dd0b", "resolution": "1080p"}}

What to ask Claude to check

ProblemHow the agent finds itTypical fix
Black edges during zooms and pansContact sheet, then preview.layout: the clip box does not cover 0…canvas_width × 0…canvas_heightRaise the scale (keyframe.add or segment.set_transform)
Text cut off or too wideText box outside the canvastext.update with a smaller size, or move it
Title covering captions or a stickerOverlapping boxes at the same timeMove one with segment.set_transform, or shift it in time with timeline.segment.move
Black frames between clipsA gap on a track in timeline.get, or a dark tileTurn the magnet on with timeline.settings.set, or move the clip
Captions out of synccaptions.list times compared with transcript.getcaptions.shift with a small offset_us
Music too loud under speechaudio.loudness on both clipssegment.set_volume so the music sits 10–15 LU below the speech

Tips

  • Contact sheets are cheap: 8–12 tiles of 240–320 px are enough to judge composition and pacing. start_us and end_us zoom in on one section.
  • preview.frame with width 960 or more is the right tool for reading small text.
  • Ask for a short change log at the end. Every fix is in the undo history, so you can step back through them in the editor.
